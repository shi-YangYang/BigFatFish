# Decision：开发命令拥有本次后台生命周期

## Context
开发桌面更新后持续复用旧 detached Runtime，造成聊天流式路由 404。用户要求 `desktop:dev` 管理全部开发进程，并确认使用当前模型配置/聊天记录，接管本项目旧后台。

## Decision
开发入口统一准备并管理 Runtime、前端及原生会话；显式开发适配覆盖后台启动/关闭职责。使用现有数据目录，可用明确 data-dir 覆盖；本项目旧实例经身份核实后优雅接管，其他实例不误停。开发退出清理本次拥有的服务，正式安装版仍支持后台常驻。

## Reason
前后端必须来自本次开发代码；仅在 UI 提供重连或要求用户每次手动重启，无法保证进程与代码一致。

## Alternatives
独立开发数据目录被用户否决；无条件复用后台会继续产生版本错配；全局杀进程会影响无关应用，不采用。

## Consequences
开发退出后本次 Runtime 不再常驻，后端源码更改重新运行开发命令。需要开发进程所有权、单实例和清理验证；不改变正式发行和 CLI 独立 daemon 的产品语义。

独立验收发现原生备份/恢复和安装更新会主动停服，与 supervisor 的异常回收冲突。托管开发入口须在副作用前明确拒绝此类维护和应用重启，保留只读检查；先结束开发会话，再使用独立 CLI 或安装版操作。此边界避免中断持久化维护，不扩张本轮为新的维护控制协议。
