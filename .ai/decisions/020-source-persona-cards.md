# Decision — 以网站完整卡为人设底稿

## Context
用户明确指出不应从零写人设，要求仅女儿版（女儿版 · 孺慕）和傲娇版（QQ 群友版官方默认卡），缺工具补齐。

## Decision
以 https://aigengtu.com/persona 两张完整卡为可追溯底稿，保留原文、作者与来源；只做工具、渠道、称呼和已有产品边界适配。替换三个原创推荐预设，默认女儿版，保留自定义/历史兼容。继续遵守用户不引用回复、限定联系人、无主动发送页面和无自动 Git 提交要求。

## Reason
原卡定义完整互动节奏、反应及工具用法，短摘要不能等价替代。女儿版明确不顶嘴，与旧原创女儿感有实际差别，采用最新指定卡。

## Alternatives
不采用从零仿写、不仅改标签、不把缺少工具的描述留为空承诺。

## Consequences
需要完整提示词存储、工具对照补齐和边界验证。外部卡文本保留原作者版权，不因仓库代码许可而声称其为原创或 MIT。现有原卡未设计的桌面/Runtime差异必须显式留痕，不静默改掉角色核心。

自动笔记使用独立 `conversation_notes` 表（schema 7→8，仅新增表/索引），按可信会话范围保存，避免把群友内容自动写成主人确认记忆。既有记忆管理不变，逻辑归档接入 memories 范围并兼容旧 schema 7 包。应用真实数据升级前按 AGENTS §24 作具体确认，代码与隔离验证先完成。

用户在代码独立验收后明确选择「现在启用（推荐）」，授权启动开发版、对当前本地数据新增自动笔记表、更新本项目内置 QQ 插件并经版本 API 切换网站女儿版；保留快照和人设历史。此授权不包含 Git 提交或推送。
