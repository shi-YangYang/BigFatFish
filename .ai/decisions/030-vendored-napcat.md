# Decision030：NapCat 源码与构建归属

日期：2026-11-20。关联 [Spec062](../../specs/spec-062-vendored-napcat/spec.md)。

用户明确选择“源码纳入仓库，由我们维护”，替代仅管理远端原版组件的分发方式。固定 NapCat 4.18.42、原 commit `9335843246e3b7a17944861f3ac8731a259732c2`，由归档仓库取得；原源码、锁文件、许可证和必要原生资源在 `third_party/napcat` 保存并记录完整性。

原源码保持不变，自有构建、校验、运行适配位于第三方目录之外。上游 workspace 只属于该组件，不改变大肥鱼单根业务模块的组织方式。源码构建在忽略的构建副本中执行，托管 QQ 真正加载该产物。QQ 客户端、Node 引导及上游原生二进制仍分别标记来源，不声称全部可以由本项目源码编译。

根许可证不是 MIT，禁止商业使用，并写明“modified code must not be publicly released”；WebUI 等子目录还带有各自许可。保留完整许可与版权，不将 vendor 内容纳入大肥鱼的 MIT 声明。本次接入不包含公开修改版或商业分发授权；以后涉及这些行为时需先解决授权条件。

Mac/Linux 保留 Docker 隔离，Windows 保留独立进程树。优先复用已核实的本地运行资源；必要归档按固定 SHA 校验，镜像按内容身份识别，不因仓库下线放宽凭据、端口、容器归属或文件检查。

本次在独立 worktree 实施并交付补丁、行为验证和回滚文件；原工作区 tracked 项目文件和 TARGET 保持不变。首次测试曾写入原 node_modules 的 ignored Vitest 缓存，已切换独立依赖副本；不声称这些缓存字节未变。不包含 commit、push、发布、真实账号重启或收费调用。
