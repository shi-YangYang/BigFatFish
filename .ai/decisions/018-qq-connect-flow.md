# Decision 018：QQ 单次连接与设置入口

## Context
用户反馈“快速连接”仍需多次启动、QQ 多层折叠难以理解，共用折叠的悬浮和点击效果不协调。

## Decision
连接编排由 Runtime ManagedQQ 管理，单次显式操作完成必要安装、启动及登录后的连接恢复；同账号复用已保存的回复范围，首次或账号变化时由用户保存必要设置后连接。暂停、取消和配置变化不得被迟到任务覆盖。QQ 使用回复设置、表情、消息三个同级入口，常用设置不折叠；共用 beUI 折叠保持轻反馈和无障碍语义。

## Reason
页面刷新不应打断后台连接流程，按钮应完成其表达的动作。清楚的内容分组减少寻找操作，不以解释文字弥补流程。

## Alternatives
仅重命名快速连接按钮仍保留重复操作；前端轮询串联安装和启动会依赖页面存活；自动猜测主人会改变已确认的账号与记忆边界。

## Consequences
保留底层组件 API 与外部 NapCat 入口，不更改主人、好友、群范围或主动消息规则。独立验证生命周期竞争条件及共享折叠交互。
