# Desktop WebUI 产品与视觉设计

## 状态

设计提案已完成；用户于 2026-11-03 明确回复“改”，已授权实施，并要求联网搜索“大肥鱼”、替换为大肥鱼娘形象。Spec 010 已实施并在 R1/R2 返工后通过新独立验收；最终生产截图与本机包证据见该 Spec Plan。产品设计与UI/UX设计两个Agent的完整报告均已处理，协调者已查看当前页面和最终预览截图。用户已结束此前P0–P7持续开发任务，此后单独进行Desktop产品精简和UI/UX改版；原开发缺项保留，不继续扩展旧Goal。

## 已确认方向

- 用户认为当前Desktop功能曝光过多，组件尺寸、颜色与排版不统一。
- 用户已选择：保留桌面窗口，里面只承载一套简洁的WebUI。
- 两个独立设计角色并行：产品设计梳理功能/导航/用户路径，UI/UX设计检查真实界面并形成统一视觉方案。
- 设计阶段交付了提案与可审阅预览，当时未改生产业务代码；用户随后授权实施。导航精简不意味着删除Runtime能力。

## 改版前事实

`apps/web/src/main.tsx`已直接复用Desktop的`App`与`style.css`。Desktop和Web不是两套需要合并的业务页面；现有差异主要是传输/认证与本机设置、备份、更新等能力。

`apps/desktop/src/App.tsx`当前Desktop为17项一级导航，Web为15项，混合日常交互、养成、平台配置、维护和调试。重新组织信息层次优先于更换技术栈或迁移源码目录。

## 产品设计提案

产品设计Agent已完成只读梳理。以下方案已交付审阅并获用户“改”的实施指令；实际结果和验收以 Spec 010 为准。

### 信息架构

| 一级入口 | 主要任务 | 次级内容 |
| --- | --- | --- |
| 聊天（推荐默认首屏） | 对话与继续历史会话 | 会话列表、消息、输入；工具结果附在消息内，语音转写/朗读并入相关操作 |
| 我的鱼 | 了解和调整这条鱼 | 人格摘要、记忆、经历/日记；编辑设定和活动计划按需进入 |
| 连接 | 接入和管理平台 | QQ、B站、抖音真实账号状态及各自连接详情 |
| 底部设置 | 配置和维护 | 模型、扩展、通用、数据、关于与更新；技术配置与诊断放高级区 |

有待审批事项时显示计数并打开统一抽屉，当前活动提供暂停入口，托盘保留暂停/退出。我的鱼使用分区或次级导航，不把全部人格表单、记忆和日记堆成一张长页面。

### 当前入口迁移

| 当前入口 | 推荐位置/处理 |
| --- | --- |
| 主页 | 取消独立入口；人格摘要移至我的鱼，当前活动留在聊天状态区，最近经历移至经历 |
| 聊天 | 默认首屏；减少列表中的内部模型ID和完整时间戳 |
| 生活 | 我的鱼 → 经历/日记；日期、生成和失败修复按需出现 |
| 记忆 | 我的鱼 → 记忆；有效记忆与待确认候选区分，保留来源和共享范围 |
| 人格 | 我的鱼 → 编辑设定；摘要优先，版本历史为次级入口 |
| 渠道、B站、抖音 | 合并为连接；现有渠道主要是QQ，明确命名。搜索/手动观看等必要操作保留在平台详情 |
| 任务 | 当前执行放活动状态，记录进入经历，计划进入活动计划，保留暂停与计划开关 |
| 权限 | 待审批抽屉；授权规则/历史放对应平台或扩展，手工QQ发送放QQ详情 |
| 模型 | 设置 → 模型；聊天无模型时提供直达入口 |
| 插件 | 设置 → 扩展；保留安装/授权/启停，JSON和直接工具调试放高级区 |
| 语音 | 上传音频转写放聊天附件，朗读放消息操作，声音配置放设置；取消常驻工作台入口 |
| 日志 | 设置 → 高级 → 诊断；异常时直达 |
| 设置、备份、更新 | 统一设置容器；数据与关于/更新分组，按Desktop/Web实际宿主能力显示 |

取消的是独立入口，已实现的Runtime能力、数据和权限契约保留。没有根据聊天界面推定所有平台操作都能由Agent完成，因此平台详情仍保留真实可用的操作。

### 关键路径与状态

1. 首启使用默认数据目录，名字可选填；未配置模型时引导配置。基础字段为提供商、地址、模型名、API Key；内部ID自动生成，预算/超时等折叠。“保存成功”仅表示配置已保存，不能冒充真实调用成功。
2. 日常默认聊天并恢复最近会话。首次发送自动建立会话为推荐新增交互，实施时保持请求隔离、取消与会话一致性。QQ来源会话仍按现有规则只读。
3. 人格按需编辑，记忆候选需要确认，来源和共享范围可核对；普通视图不同时堆内部ID/版本号。
4. 平台状态区分未设置、需登录、已连接、异常、已停用。QQ连接配置、B站扫码、抖音专用浏览器是不同流程，安装插件不等于账号在线。
5. 审批展示平台、账号、动作、目标、正文/媒体及有效状态；批准一次或拒绝。动作变更需重新批准，结果未知先核对平台。插件授权和对外动作审批分别处理。
6. Runtime断连保留页面、会话和草稿，并给恢复操作；不将断连再次呈现为首启。区分Runtime未运行、模型失败、平台掉线和浏览器管理登录过期。

当前语音能力是上传音频转写与文字合成，未实现麦克风录音；本轮不把“按住说话”加入既有能力。抖音私信/分享/投稿发送协议仍未完成，状态保持准确。

### 桌面壳与共享界面

沿用现有`api.ts`适配：Desktop经Tauri `runtime_request`，浏览器经同源`/api`与管理会话/CSRF访问。共享页面可以重组，不需要新的本机HTTPS网关或桌面管理口令登录。

Tauri继续承接Runtime生命周期、受控本机访问、数据目录、托盘、后台运行、登录启动和更新。这些设置按宿主能力呈现；浏览器端不冒称能控制访问者电脑的开机启动。关闭窗口、后台运行、退出停服的含义保持明确。

## UI/UX设计提案

### 已实测问题

当前页面直接加载生产React/CSS，用隔离示例数据替代Tauri读取；没有启动真实鱼。以下为设计阶段采集的问题证据；后续生产修复见 Spec 010。

| 优先级 | 现状证据 | 原因/改版方向 |
| --- | --- | --- |
| P1 | 1100×760窗口下导航两行、高125px，聊天输入区底部819px，发送入口在视口外 | `.chat`固定`calc(100vh - 170px)`未适应导航换行；改为外壳/消息区/输入区明确分配空间 |
| P1 | 17个同级按钮同时曝光聊天、维护、平台和权限 | 按产品方案重组为三个主入口和底部设置 |
| P2 | 模型页“新建配置”与配置标识混排，按钮42px、输入39px、下拉41px，字体16/14px混用 | `Models.tsx`将操作、标签、字段作为同一两列Grid的直接子节点；拆分操作区与字段组，定义统一控件 |
| P2 | 发送/保存缺少明确主操作外观 | 默认提交按钮未显式写`type="submit"`，不能被CSS属性选择器命中；使用明确的按钮样式变体 |
| P2 | 选中会话中的元信息仍暗灰，普通卡片/表单受全局元素样式影响 | `.chat small`未适配选中背景；用清晰组件/状态样式替代泛化元素规则 |
| P2 | 首页图形和同权重卡片占据主要空间，少量内容显得很重 | 聊天为默认主任务，养成内容按次级分区展示，减少无必要卡片 |

已纠正初始静态推断：`.settings`实测仍为Grid，没有被Flex覆盖；不能以该错误推断作为修复依据。

### 统一视觉规范

| 项目 | 推荐值/规则 |
| --- | --- |
| 侧栏 | 220px；701–960px窗口为188px；≤700px收起为导航抽屉 |
| 主区 | 顶栏64px；聊天最大720px，普通内容最大920px，设置容器680px、内部表单约600px |
| 滚动 | 外壳占窗口高度；聊天消息独立滚动、输入区保持可见；设置长表单在内容区滚动 |
| 字体 | 系统中文字体；正文14px、聊天15px；标题24px、分区18px、标签13px、辅助状态12px |
| 控件 | 普通按钮/输入/下拉40px；紧凑按钮32px、图标按钮36px、导航42px，按职责固定变体 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 40px；字段组16px，分区24px起 |
| 圆角 | 控件8px，容器12px；列表和文字不机械套卡片 |
| 基础色 | 背景`#f7f8fa`、白色内容面、侧栏`#f1f3f4`、正文`#202b33`、次要文字`#65717b`、边线`#e2e6e9` |
| 强调色 | 主色`#216b5a`、浅选中面`#e6f1ec`；待确认用琥珀、失败用红，配合状态文字 |

空会话给简短输入引导；无模型给添加入口；加载保留布局并局部反馈；错误在发生位置持续显示原因与可执行操作。预览的短Toast只演示本页交互，不能成为生产错误反馈的唯一形式。记忆/经历为空时不填充虚构成长数据。

## 边界与后续

保留Runtime、现有数据及权限契约；必要本机能力由轻量桌面壳承接。视觉预览仅为设计草稿，示例内容不作为真实鱼的数据或已实现功能。

推荐实施顺序：先重组共享App外壳/导航并修正聊天高度；再提取确有共用语义的Button/Field/Status/Drawer；随后迁移我的鱼、连接和设置；最后接回首启、断连、请求状态与待审批。保持普通源码组件，不新建公共包或迁移目录。录音、插件市场、新平台发送协议不纳入这次界面改版。

实施验收应覆盖：三个主入口加设置；已配置模型可直接聊天；无模型/断连/审批有清楚下一步；草稿与会话不因断连丢失；授权和未知结果保持明确；Desktop/Web共用页面而按宿主显示能力；既有本机维护仍可找到；规定窗口宽度下无横向溢出，聊天发送区始终可见。用户已确认落地上述导航/默认首屏与视觉方向；最终生产行为及验证记录以 Spec 010 为准。

## 后续修正：蓝色主题与组件基础（Spec 011）

用户在 db9cd5e 交付后明确要求使用 DS 蓝色，并指出仍有对齐/尺寸不一致，允许采用UI库或手工封装（库推荐beUI）。此前提案的绿色品牌色由此被用户最新要求替代，不再作为实施约束；原图标/导航与业务保护保留。

2026-11-03 已核实 [DeepSeek 官网](https://www.deepseek.com/) 实际CSS中 `--ds-color-brand:#4d6bfe`。品牌基础采用此蓝，常规正文与白字按钮可用稍深同色系保证可读性（计算白色对 #4D6BFE 为4.33，对 #3959E4 为5.64）。

已查阅 [beUI theme](https://beui.dev/docs/theme)、[Button](https://beui.dev/components/motion/button) 与其官方源码仓库；它依赖 Tailwind4/Motion，支持复制组件源码。本项目目前没有这些依赖，按用户明确允许的方式手动建立基础语义组件并迁移现有使用点。本轮不引入其他UI库，不把此取舍表述为beUI不兼容或已经接入。具体范围、实际布局证据与验收见 Spec011。

Spec011 已落地并独立复验 PASS：共享原生控件覆盖 Desktop/Web，常规控件40px、显式紧凑动作32px，使用操作行/字段网格消除混排和间距不一致；确认区遗漏经新实施/新验收关闭。蓝色生产截图位于 docs/design/desktop-webui-{chat,settings,general,data}.png；最终产物与验证边界记录在 Spec011 Plan/Acceptance。旧绿色预览仅为历史。

## 布局收敛（Spec 012）
用户截图明确指出宽主导航、双顶部栏与常驻会话侧栏重复占位；本轮把宽主导航改为约72px窄导航，合并聊天顶部操作，历史按需浮层展开。入口和状态仍保留，消息/输入保持居中阅读宽度。此项取代Spec010的宽导航与常驻历史展示方式；不改变业务信息架构或数据边界。

已实现72px导航、60px单顶栏和720px阅读列，并通过新独立验收。历史复用现有Drawer，在选择/Escape/关闭后恢复焦点；App与Chat通过显式React节点组合头部，业务状态仍由Chat持有。最终截图/验证/包证据见Spec012，按用户持续授权本地提交。

## 明确切换beUI（Spec013）
用户认可当前布局，但指出新对话和待审批按钮尺寸仍不一致，明确要求换成beUI。这项指令取代Spec011手封Button方案；本轮实际引入官方源码Button与Tailwind4/Motion依赖，统一全部按钮入口与顶栏尺寸，保留当前布局。beUI为源码分发，保留固定上游和MIT；不安装同名未知库、不声称仅CSS修补就是接入。原生输入/选择等事件协议本轮保持，避免与按钮问题无关的业务表单迁移。

Spec013已实现并独立PASS。采用基础Motion Button及薄兼容入口，移除旧基础按钮CSS，按实际14px根字号设置px尺寸；顶部40px/8px圆角、桌面文字100px最小宽度，保留reduced-motion。Tailwind不启用Preflight，语义token映射到DS蓝；许可证随双前端打包。版本和接入边界见tech-stack与Spec013，依赖仅增前端dev项。
