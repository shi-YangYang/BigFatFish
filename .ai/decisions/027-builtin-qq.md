# QQ 从插件转为内置能力

用户明确要求三平台逐步成为固有能力，这轮先做 QQ。Spec055 已本地提交 6fd50d2；内置化新改动不自动提交。

将项目自己的 QQ 协议适配代码并入 Runtime，静态导入、随应用更新，运行和权限由连接模块管理。退出插件目录、动态装载和独立包升级流程；保留第三方扩展系统与 channel.send。旧配置、账号资料和数据保留，旧插件停用意图迁移为连接停用；旧安装代码不再加载。

底层沿用原版 NapCat 4.18.42 和现有隔离托管。其[固定版 LICENSE](https://github.com/NapNeko/NapCatQQ/blob/9335843246e3b7a17944861f3ac8731a259732c2/LICENSE)含修改与公开发布限制，当前仓库 README 也要求基于代码开发先获主作者许可。此次直接使用已有自有协议适配器，不复制/修改受限源码；这不影响 QQ 成为产品内置能力。B站、抖音留待后续明确任务。

不为了名称整洁改动历史配置表，不删除用户旧插件目录；备份恢复仍暂停外部活动。具体范围与兼容要求见 [Spec056](../../specs/spec-056-builtin-qq/spec.md)。
