# 网页设计与前端组件规范

本规范适用于大肥鱼桌面窗口中的 WebView 界面。设计应服务于用户理解信息、作出决策和完成操作，而不是解释产品或技术实现。

## 基本规则

1. **精简内容**：只保留必要信息，删除冗余描述、解释性小字和重复内容；不要为填充页面而添加文案，也不要习惯性地为每个模块添加副标题或说明。控件已经表达的规则不重复，例如「主人只能有一个 QQ」；模型路由和内部协议留在开发文档。
2. **面向用户**：只展示用户实际需要的信息、状态和操作；禁止将开发说明、技术实现、设计意图或 AI 自我解释写进用户界面，避免空洞的营销话术。
3. **统一语言**：中文网页统一使用简体中文；除品牌名、专有名词及必要技术术语外，不随意中英文混用。同一概念的称呼应保持一致。
4. **兼顾美感与信息呈现**：根据页面用途和内容特点安排布局、留白与视觉层级，控制信息密度，突出主要内容与关键操作。避免给不同用途的页面套用同一模板，也避免堆砌说明文字和无意义的装饰。沿用浅海蓝主题和语义色（`apps/desktop/src/styles/`），用间距和层级分组，不靠多层顶栏或嵌套卡片划分内容。
5. **保持一致、易用**：同一页面的同类组件尽量保持尺寸、配色、操作方式和状态反馈一致，不同页面可按用途调整。按钮与操作名称应清楚直接，重要状态、错误信息、操作风险及限制必须明确呈现。同组表单的标签与输入框对齐，保持一致的字段间距、控件高度和按钮基线；窄窗口可换行。长操作记录在卡片内滚动，不让整个页面跟着滚。
   等待扫码、待手机确认是正常状态，在连接卡片内提示即可；耗时操作在相应按钮或区域显示加载状态。真正失败时就近说明原因和下一步，不在页顶重复报错。
6. **优先复用 UI 组件库**：先看 `apps/desktop/src/components/` 中已封装的控件；需要新组合时优先使用其 `beui/` 源码组件。用共享样式定制外观，按需封装业务交互。已有组件不适用时再自行实现，不引入第二套同类库。

## 检查标准

逐项检查用户可见内容：用户真的需要看到吗？能否缩短或删除？是否在解释内部实现？有无不必要的中英文混用？关键操作与必要提示是否清晰？

**最终要求：界面简洁、自然、直观，优先展示信息与操作，而非描述界面本身。**
