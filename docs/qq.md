# QQ 渠道

BigFatFish 使用仓库内固定源码构建的 NapCat，在应用内准备 QQ 运行环境、扫码登录并设置回复范围，也保留连接已有 OneBot 11 服务的方式。NapCat 是独立的第三方组件，遵循其自身的[许可证](../third_party/napcat/LICENSE)，不属于大肥鱼的 MIT 授权。请使用专用 QQ 账号，扫码与设备验证由用户完成。

## 快速连接

1. 打开「连接」，在 QQ 卡片点「管理连接」，再点「连接 QQ」。缺少组件时会自动下载并启动，无需分别准备、启动。
2. macOS/Linux 需要本机 Docker 已安装并启动，且使用 Linux 容器；Windows x64 使用独立原生组件。Windows arm64 可连接已有服务。
3. 首次连接时，用手机 QQ 扫码并确认；二维码过期可点「刷新二维码」。之后在同一台机器上用原数据目录重启，大肥鱼会先尝试恢复上次登录的 QQ。即使还没保存回复设置，也可以恢复登录，但不会开始回复。登录失效或 QQ 要求验证时，再用手机扫码。
4. 首次登录或换账号后，在「回复设置」选择主人 QQ 和允许回复的好友、群，点击「保存并连接」。不会自动猜测主人或授权联系人。之后修改使用「保存设置」。

QQ 页面以「回复设置 / 自主活动 / 表情 / 消息」四个页签组织。托管组件登录后，「回复设置」列出好友和群。主人可从好友中选择，也可手动输入 QQ 号。列表不可用时可手填好友或群号。新增好友或加入群后，点右上角的「刷新好友和群聊」图标。已有草稿保留，新联系人需自行勾选并保存。群默认普通消息也可回复，也可选择仅被 @ 时回复。主动消息默认关闭。
内部地址、端口和两套随机凭据由 Runtime 管理，无需填写；机器人 QQ 从真实登录信息读取，不推断主人身份。「已登录」表示组件确认账号已在线，页面顶部「已连接」还要求内置 OneBot 客户端完成账号与健康检查。

手机确认后，账号卡会先确认登录，再连接消息服务。这时不用重复扫码或退出 Mac 上的 QQ。短暂中断会自动重试；持续约一分钟仍未就绪时，可以点「重试连接」。如果显示「QQ 已离线」，请重新连接并登录。凭据被拒、账号不符或组件出错时，卡片显示具体原因。状态暂时读不到时，可点「重试」更新。保存回复设置出错时，提示显示在设置表单内。

「断开连接」同时停止渠道及所属组件，设置保留。再次点击「连接 QQ」即可恢复；渠道单独暂停但组件仍在线时显示「重新连接」。准备和启动期间可取消。暂停、取消、配置变化或换账号会阻止之前操作迟到恢复连接。正式安装版关闭窗口到后台时，QQ 继续在线。退出后台或关闭开发版时，QQ 组件也会停止。macOS 和 Linux 正常重启会复用原容器，Windows 会沿用原数据目录。如果 QQ 已判定登录失效，仍需用手机确认。

组件存于当前数据目录的 `data/qq-component/`，QQ 登录数据与日常 QQ 隔离。Mac 不修改 `/Applications/QQ.app`，Windows 不修改系统 QQ/注册表。便携逻辑备份不包含组件程序、QQ 登录态或容器身份；迁移后需重新准备和登录，恢复配置保持停用。

## 连接已有服务

已有 NapCat 的用户点击「连接已有服务」（托管组件已登录时从「连接选项」进入），填写地址、连接凭据、机器人 QQ 与主人 QQ。NapCat 需开启 OneBot 11 正向 WebSocket，消息格式为数组；本机允许回环 WS，远端必须使用 WSS。填写完成后点击「保存并连接」，无需另勾选启用。反向 WebSocket 和 HTTP 上报未接入。

凭据留空保留原值，不会在查询接口返回；必须可用于 HTTP Authorization 头，不能包含中文、表情、空白或控制字符。非法值在保存前拒绝，保留原连接。切换到内置组件前请先停用已有服务；组件不会接管其他 NapCat 或 QQ 进程。

已有不合法连接凭据导致初始化失败时，仅 QQ 显示凭据错误；本地 Runtime 和聊天仍可使用，可在渠道设置中填写有效凭据后恢复。主密钥文件缺失仍会安全拒绝启动，不会生成替代密钥。

主人只能有一个，其他私聊账号必须明确列入好友允许列表；群必须明确列入允许列表。群触发可选普通消息或真实 @，旧配置缺省为普通消息。昵称、自称主人、CQ 字符串不授予身份。每位作者与私聊/群聊会话隔离，账号、主人或授权配置改变后建立新引擎会话。QQ 消息保存在各自的渠道会话中。桌面和 Web 的聊天页只显示本地对话。

## 记忆与发送

在「连接 → QQ → 回复设置 → 主人 QQ」选择或填写自己的 QQ 并保存。在允许回复的群里，大肥鱼也能认出该账号，但不会带出桌面和私聊中的称呼、偏好或观看记录。好友和其他群友不能靠昵称或自称成为主人。

授权的 QQ 对话在回复成功或大肥鱼选择静默后进入后台记忆队列。整理完成后，主人在群里亲口说过的偏好和已确定的安排，也可在桌面或主人私聊回忆。每位好友的私聊分别保存；同一群按实际发言人记录，其他群不能调取。在「我的鱼 → 记忆」可查看归属与来源，编辑或删除。点击「共享给 QQ」仅共享选中记忆的内容，原始私聊摘录保持私有。撤销或更改已披露的记忆后，公开会话会重新检查，阻止已失去权限的回复发出。

已授权入站回复可自动发送。开启主动消息权限后，CLI、B站分享和具备 `channel.send` 权限的插件可向授权对象发送消息，使用同一发送服务。停用、撤权或配置变更会取消在途生成并阻止尚未发出的消息；已进入外部发送的消息无法撤回。

旧 QQ 审批接口返回 `QQ_APPROVAL_REMOVED`，历史待审批项不会自动发送。旧插件 `channel.propose` 权限不升级为直接发送，采用 `channel.send` 需要重新授权。B站分享到 QQ 也检查同一发送权限。抖音已支持的互动按其账号授权直接提交。获准好友可以使用自己的私聊记忆和已共享内容，身份由绑定的账号决定。

`sent` 仅表示协议服务返回成功和消息 ID，不代表对方已读。自动回复生成失败记录为 `failed`，与外发前因权限或健康检查被阻止的 `blocked` 分开；取消与重启中断记录为 `interrupted`。`unknown` 表示外发请求发生后超时、断线、异步接受或不明确响应；不会自动重试。请在 QQ 人工核实后再决定是否重新创建消息。重复入站消息跨重启去重，重启期间尚未完成的生成标记中断，正在发送的记录标记未知。投递记录仍可通过 CLI 或 API 查询，历史数据保留。

「连接 → QQ → 消息」的操作记录按时间显示最近 20 条需要处理的问题，包括回复生成失败、消息未发送、部分发送和发送结果待核实。同一轮回复只占一条；遇到部分发送或结果待核实，请先到对应的 QQ 私聊或群聊核对。停留在页面时列表自动更新，较长记录在卡片内滚动。消息问题与自主操作记录分别读取，一项失败时仍保留另一项；可点击重试。若自主活动或记录提示「请重新启动大肥鱼」，请退出后重新打开；开发版需重新运行 `npm run desktop:dev`，仅刷新页面不会更新后台。完整审计保存在本机，可用 `channels audit` 查看近期原始事件，用 `channels deliveries` 查看投递状态和错误码。

OpenAI 兼容模型的新调用会保存受限错误码：`MODEL_HTTP_502` 等表示实际收到的模型 HTTP 状态，`MODEL_NETWORK_ERROR` 表示连接失败，`MODEL_STREAM_INTERRUPTED` 表示响应中途断开。错误正文、密钥和请求内容不写入错误字段。取消优先于网络错误，不自动重试。未取得详细诊断时保留通用模型失败；旧 `MODEL_RUN_FAILED` 不能据此追认具体服务端故障。

## 媒体范围

完整P7接口、NapCat前置条件与运行证据边界见 [开发与协议](developer.md#qq-媒体与实际协议)。

- 入站识别文本、图片、语音、文件、真实提及及引用消息。只通过同账号的 `get_image` / `get_record` 获取有大小限制的媒体字节，不跟随消息里的 URL 或本机路径。聊天模型可用 `get_message_images` 查看本条图片，语音由 `asr` 转写。托管组件自动开启图片字节返回；已有服务需开启 NapCat 的 `enableLocalFile2Url` 才能取得图片内容。文件只保留安全元数据。
- 自动回复不引用原消息，支持最多3条短消息（合计4000字）和一张独立气泡表情，模型通过工具明确分条，普通最终文本不按标点机械拆分。输入最多 64 个段；不支持的消息段和畸形事件不会进入模型。
- 主动媒体可通过 CLI JSON 发送 PNG/JPEG 图片、WAV/SILK 语音，单个最多 2 MB，总段数据不超过 2.8 MB。P7支持单独发送最多2MB的TXT/PDF文件，upload_private_file/upload_group_file本身即实际发送，不再发送第二条消息。长媒体与视频仍不支持。
- 手动发送只接受本机认证入口明确提供的媒体字节，经格式和大小校验后转为 OneBot `base64://`；不接受任意 URL、路径或入站缓存文件名。协议服务仍可能因媒体编码或账号状态拒绝请求。

此边界依据固定 NapCat `98d781d19815d1625b24d717ce280ecf0a4f6d0c` 的 `packages/napcat-onebot/api/msg.ts`（`handleOb11FileLikeMessage`、`handleObfuckName`）及 `packages/napcat-common/src/file.ts`：缓存名未命中可回落到本地文件解析，因此不透传缓存名。OneBot 11 标准 `message/segment.md` 明确支持图片/语音 base64 输入。详情和许可见 [上游记录](upstreams.md)。协议适配仍由大肥鱼实现；固定版上游原始源码另存于第三方目录。

## CLI

沿用 `--data-dir PATH --json`。配置和发送 JSON 通过标准输入传入，避免把 token 放命令行参数或 shell 历史。

```sh
node dist/cli/src/main.js channels status --json
node dist/cli/src/main.js channels configure --json < /private/path/qq-config.json
node dist/cli/src/main.js channels start --json
node dist/cli/src/main.js channels deliveries --json
node dist/cli/src/main.js channels send --json < /private/path/message.json
node dist/cli/src/main.js channels audit --json
node dist/cli/src/main.js channels stop --json
```

配置示例（`revision` 取当前 `channels status`；首次为空字符串；`token` 省略保持、空字符串清除）：

```json
{"revision":"","url":"ws://127.0.0.1:3001","accountId":"机器人QQ号","ownerId":"主人QQ号","friendIds":["好友QQ号"],"groupReplyMode":"all","groups":[],"enabled":true,"replyEnabled":true,"proactiveEnabled":false,"token":"自行填写"}
```

发送输入示例（需已开启主动消息权限）：

```json
{"target":{"kind":"private","id":"主人QQ号"},"segments":[{"type":"text","data":{"text":"要发送的消息"}}]}
```

图片段是 `{"type":"image","data":{"file":"base64://文件字节的Base64"}}`；语音使用 `record`，不接受其他附加发送参数。发送 API 为 `POST /v1/channels/qq/send`，正文同上，返回 `{id,status}`；仅 `sent` 表示协议确认。HTTP中断时先查询发送记录或真实 QQ，不自动重试。

## 表情回复

连接 → QQ → 表情分为「网络表情」和「本地表情」两个区域：前者设置网络图库，后者预览和启停内置、上传及聊天收藏的表情，点「添加表情」可上传 PNG/JPEG（单张最大 2 MB）。添加时填写名称和适用场景，方便大肥鱼按语境选择；本地库最多 48 张、总计 24 MB。自添加图片可以删除，内置图片可停用。随应用附带的是三张基础表情；你上传的图和鱼在聊天中收藏的图留在自己的本地库，不随应用分发。

「网络表情」默认开启。QQ 连上后，大肥鱼会在后台准备[梗鲸图库](https://aigengtu.com/)的目录，不会提前下载图片。配图时，本地和网络表情一起按语境挑选：一样贴切时优先没在这段聊天里发过的，再让本地图稍微靠前。比如刚发过本地的「求夸夸」，下次撒娇就可以换一张贴切的新图。关闭网络表情后只从本地挑；没有合适的图，也可以只回文字。

每轮最多查看三张、选择一张表情；文字和图片分开气泡，也可只发表情。模型工具的选择仅为待发送状态；最终发送仍检查账号、回复范围、取消状态、记忆范围及图片是否被停用/删除。发送结果未知时不会自动重试。此能力仅用于 QQ 自动回复，桌面聊天和其他平台没有因此获得自动发图能力。

日常问候、撒娇、庆祝、接梗和晚安等情境会鼓励大肥鱼主动配图，不用先说“发个表情”；认真讨论、当前人格或对方偏好只用文字、没有合适图片时仍用文字。它会优先选同样贴切的新图，不强制每几轮配图。每个 QQ 账号下的私聊和群聊分别记住最近八张表情，同群不同成员共享记录；已确认或可能已投递的图片用于避重复，失败或取消的不计入。记录仅存在当前 Runtime 内存中，重启后重新积累；未知投递仍是未知结果。真实模型的自然使用频率会有差异。

本地表情与网络开关保存在 SQLite，并随「插件」范围的逻辑备份导出；schema 6/7 的旧备份仍可恢复。网络候选仅保留在当前回合，不写入本地库。

API：`GET/POST /v1/channels/qq/stickers` 获取元数据/上传，`GET /v1/channels/qq/stickers/:id/image` 读取图片，`PUT /v1/channels/qq/stickers/:id` 以 `{revision,enabled}` 修改状态，`DELETE /v1/channels/qq/stickers/:id` 删除自添加表情；`GET/PUT /v1/channels/qq/sticker-options` 读取/保存 `{networkEnabled,revision}`。这些接口沿用 Runtime/网页认证，不在图片 URL 中传递密钥。

托管编排 API：`POST /v1/channels/qq/component/connect`，共用现有认证与组件任务锁；响应表示任务已开始，最终连接状态仍以渠道健康检查为准。原 `install/start/stop/refresh` 入口保留供既有调用方使用。


## 人设卡工具

原卡的 `send_message`、`send_sticker`、`send_poke` 先暂存本轮动作，生成成功后按顺序投递，只作用于当前获准聊天。模型先完成读取和看图，再在最后同批提交需要的文字、图片和拍一拍；固定 DSH 的 `concludeTurn()` 在整批完成后结束回合，不再为工具收尾额外请求模型。同批任一工具失败则本轮不投递；早先已恢复的工具失败不会误拦截成功回退。明确静默使用 `skip_reply`，不记为生成失败。拍一拍每轮最多一次，只拍当前发言人；仅机器人收到拍一拍时产生入站回合，不产生自我循环。NapCat依据[官方 send_poke 文档](https://napneko.github.io/develop/api/doc)，不可用或拒绝时如实记录失败。QQ 协议客户端随 Runtime 更新，无需单独安装或升级插件。

每条消息真正发送前重新核验账号、范围、取消、记忆与图片资格；失败或结果未知后停止后续动作，不自动重发。部分发送在操作记录标明。工具已排入的文字不会再用模型最终总结重复发一遍；这些聊天工具不会自行启动定时私聊或群发；自主更新资料和发布说说见下节。

有人发来适合接梗的 PNG/JPEG 表情时，大肥鱼可以先看图，把值得下次用的收藏到「本地表情」，不用专门说“收藏”。它挑的是可以复用的反应图，不是把聊天里的照片、截图和二维码都存下来。同一份图片不会重复收藏。这里是大肥鱼自己的表情库，不是手机 QQ 的收藏夹；不喜欢的可以停用或删除。

## 自主活动与互动工具

QQ 是 Runtime 的内置能力。开发版重新运行 `npm run desktop:dev` 即加载新版；安装版随应用升级，不再到扩展页安装或更新 QQ。原有连接配置、主人和联系人范围继续保留；之前停用或卸载 QQ 插件的用户仍保持断开，需要时在「连接 → QQ」重新连接。旧插件代码不再加载，旧文件保留。

「连接 → QQ → 自主活动」可设置大肥鱼自己更新头像/资料、自己发说说，以及说说可见范围（默认好友可见）。沿用原版 NapCat 4.18.42；已有服务需支持对应接口。等待扫码时不执行，连接后每小时最多判断一次、每天最多6次；可以选择休息。大肥鱼不限制每天发几条说说。QQ 资料、头像和空间资料仍各限每天更新一次。暂停活动或关闭对应开关会停止后续操作。判断会使用已配置的聊天模型额度。

大肥鱼能查看当前聊天最近 20 条消息和引用原文、撤回自己的消息、改自己的群名片，也能给当前发言人点赞、对消息表情回应。允许回复的群里，群友可以问「本群公告写了什么？」「群里有哪些精华消息？」或实际 @ 某位成员问他的群名片。不会查其他群或整群名单；群设为“仅 @ 回复”时，也要 @ 大肥鱼。

主人在群里可以这样说：

- 「发条说说庆祝毕业」：让鱼围绕这个主题自己写。要指定原文，可说「发条说说，内容是今天毕业啦！」。
- “以后你的 QQ 昵称就叫小蓝”“把你的个性签名改成「今天开心，继续游！」”：改的是 QQ 账号。只想改本群显示的名字，就说「把你的群名片改成小蓝」。
- 「换个头像」：从已启用的内置表情里选。也可以在**同一条消息**附图，说「用我这张图发条说说」；有多张就说「用第二张图发条说说」。鱼先看图再用，不会自动拿群友的收藏或以前的照片公开发布。

改签名时也可以让鱼自己写。例如主人说“大肥鱼改一下你的签名”，鱼问“改成什么？”，主人紧接着回“改成你现在的心情”。鱼只用在这个群里的心情来写，不会公开私聊内容。如果指定了签名原文，就按原文改。

不用照着示例说。比如「签名那栏写上『今天也在游！』」，鱼可以理解为改自己的 QQ 个性签名。只说「换个名字」而没说是 QQ 昵称还是群名片时，应先问清楚。意思明确、权限允许时，鱼会直接操作，按 QQ 返回的结果告诉你。

群友不能代主人发令；群聊不能查看旧说说或私聊记忆。修改资料时未指定的字段保持不变。自主任务只接收人设、心情标签和自身公开资料，不读取私人聊天、长期记忆、日记或历史说说正文；自主配图限内置素材。主人私聊仍可查询最近 10 条说说，程序会阻止重复发布。

消息页只显示需要处理的问题，最近20条在卡片内滚动。说说拿到动态 ID 才算发布成功。只改签名时不会提交昵称。QQ 返回异常，但读到的签名已经是目标内容时，就按已核实处理；读不到结果时记为待核实，不会再发一次。头像只报告 QQ 已接受更新，不代表各端缓存已刷新。超时或断线后的结果待核实，程序不自动重发。恢复备份后自主活动关闭，历史运行任务不重放。

本轮使用隔离协议与模型夹具验证；尚未在真实账号修改资料、头像或发布说说，不能把接口接入当作真实QQ账号成功验证。
