# Spec — 取消平台逐条审批

状态：Done，2026-11-06。用户已明确选择「全部取消，操作直接执行」。

## 背景
QQ 已在 Spec025 改为直接发送，但抖音和全局审批入口仍然保留，导致用户继续看到待审批。
## 目标
所有已支持的平台操作不再经过逐条审批；一次发起即执行，结果由操作记录呈现。
## 非目标
不新增社交能力、不扩大联系人或账号权限、不启用未验证的抖音发送协议，不自动发送历史待办，不修改真实账号配置，不自动 commit / push。
## 当前行为
App 轮询抖音审批并显示顶栏计数、运行状态菜单入口和抽屉；抖音互动先创建提案再批准；CLI 同样提供提案/批准/撤销命令。QQ/B站分享已直接发送。
## 目标行为
移除审批计数、入口、抽屉、列表、专属状态及轮询。抖音点赞/评论表单一次提交直接创建执行任务，显示提交反馈并可查看操作记录。CLI 与 Runtime 使用同一直接操作入口。
## 功能需求
- Runtime 采用新的直接操作 API，输入包含 tool、args、requestId；以 TaskQueue 的幂等和取消机制管理任务，不在内部创建并自动批准审批项。
- 保留账号/插件授权、活动暂停、配置版本、取消、精确动作参数绑定、单次提交和真实收据检查；结果未知不自动重试。
- 旧审批 API / CLI 操作明确退役，不能悄悄转为外发；旧数据库审批记录不执行、不破坏性清除，旧 schema/归档保持兼容。
- QQ、B站的已授权直接发送行为保持。平台操作记录和插件授权界面保持，插件授权不是逐条审批。
- Desktop/Web 共享 UI 同步清理；删除无用审批组件、状态、样式和活跃流程文案。当前使用文档同步；历史规格保留原始结论。
## 边界条件
重复 requestId 不重复提交；不同输入复用 ID 明确拒绝。排队取消、执行前撤权/停用/账号变化应阻止提交；提交后断线等不确定结果记为未知。已有 pending/executing 历史审批不会因升级触发发送。
## 技术约束
EXISTING；保留原目录、浅海蓝和 beUI。不引入新依赖或 migration。用隔离夹具验证，不操作真实平台，不付费调用模型。
## 兼容性要求
旧审批接口返回明确退役错误；新调用方统一新入口。历史表仅作为兼容数据保留，不能有仍可执行的审批链。
## 验收标准
- [x] Desktop/Web 不再显示或请求逐条审批，活动暂停与平台操作记录可用。
- [x] 抖音已支持的互动一次提交即执行，CLI/API 行为一致。
- [x] 旧入口不创建/执行审批，历史审批不重放。
- [x] 幂等、取消、账号/权限/参数检查与未知结果保护有效。
- [x] 同根因调用与当前文档已同步；定向检查通过、新独立验收 PASS。
## 待确认问题
无。用户已明确取消全部平台逐条审批；权限范围和未支持协议保持。
