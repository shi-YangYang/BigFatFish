# Spec060：CI 只做跨平台运行与编译

状态：Done，[独立验收 PASS](acceptance.md)。风险：S3（构建与 CI）。

## 背景与当前行为

Windows 日志显示 Rust release 编译已经完成，后续进入 MSI/WiX candle；这些 unused 警告没有阻断编译。远端旧工作流同时重复三系统全量通用检查、准备便携包以及 macOS/Windows 安装包，且没有 Cargo 缓存或执行超时。无法仅凭末行证明 candle 长时间停留的具体原因。

## 目标与目标行为

用户已确认：「让我手动生成，ci只测试运行和编译啊」。PR/main 保留单个 checks 工作流；跨系统差异在 CI 测试，完整业务验证按风险在本地执行，安装包由用户手动生成。

## 功能需求

- Linux、Windows、macOS 均编译并运行 Runtime/CLI 的系统相关测试，覆盖进程生命周期、隔离目录和权限等真实系统行为。
- macOS、Windows 保留 Rust 原生宿主编译及其相关单元测试，不运行安装器；Linux 保留 Runtime/CLI 和容器运行验证，沿用当前产品平台边界。
- Desktop/Web 共享前端必须仍有编译覆盖，避免仅跳过构建。
- 不在 CI 重复执行全仓 typecheck、lint、全量业务测试；保留这些本地命令和原断言。
- 移除自动准备发行目录、MSI/NSIS/DMG、更新归档与产物上传；本地 desktop:build、release:prepare 仍可生成原有产物。
- 增加按分支/PR 的旧运行取消、合理超时、Rust 缓存；任务名称与日志要能区分编译和测试。
- 修正 updater.rs 中平台专属代码导致的 Windows unused 警告，不改变更新行为。

## 非目标

不调查或保证修复 WiX 本身；不增加安装包工作流，不发布/签名，不升级依赖、不调整产品功能，不操作真实数据或账号，不 commit/push/取消既有远端运行。

## 技术约束、边界与兼容

保留 Spec058 的触发去重，以及待提交 Spec059 全部类型修复。显式选择已有系统相关测试，不用空资源冒充可运行发行包。编译专用 Tauri 配置不得影响本地正式安装。仅为所选测试修正有依据的跨平台路径断言，不扩展业务修复。

## 验收标准

- [x] CI 无安装器、归档、上传和重复全仓检查，三系统 Runtime/CLI 及 macOS/Windows 原生编译保留。
- [x] 所选平台检查在本机实际通过；Mac Rust 编译/测试与前端构建通过，资源配置不会依赖残留便携包。
- [x] CI YAML、命令和缓存路径一致，超时与并发规则有效；Windows unused 警告按 cfg 修正。
- [x] 本地打包命令不变，贡献/安装文档反映 CI 和本地职责；新独立验收 PASS。
- [x] 清楚区分本机证据与未运行的新 Windows/Linux 云端 CI，不重复已有通过检查。

## 待确认问题

无。安装包是否每 PR 生成已由用户明确选择手动。
