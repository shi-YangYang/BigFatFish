# Spec 030：同步 B站与抖音连接体验

状态：Done。最终独立验收见 acceptance-r2.md；R1、R2均已关闭。

## 背景
用户在 Spec029 QQ 简化完成后要求“其它连接也要同步一下”。本轮限定 B站、抖音已有连接页与必要后台编排。dev 基线 2d28503，开始干净。

## 目标
统一清楚的连接状态卡片、单一主要连接动作和同级功能页签；不再要求用户分别启用、保存、打开登录和验证。

## 非目标
不新增平台能力、不更改审批/外发权限、不修无关活动计划、不升级依赖或打包发行、不测试真实账号或付费模型。

## 当前行为
B站先启用再扫码/验证；凭据导入隐藏在折叠中，搜索、观看、记录和分享全堆在同页。抖音先展开设置勾选启用并保存，然后打开登录、检查登录、验证账号；设置和互动折叠，任务和审批堆在页尾。

## 目标行为
- 两页沿用 QQ 的浅海蓝 beUI 卡片、40px 控件与单一主动作。用少量同级页签组织观看/记录/设置；抖音互动与审批有清楚入口，不保留多层折叠。
- B站“连接 B站”自动启用并验证已有凭据；需登录时展示二维码，扫码后自动核验并更新真实状态。取消、过期、失败可以清楚处理。保留手动凭据导入为次级登录方式，导入验证保存合为一个动作；保留既有匿名读取能力，不能强制所有搜索必须登录。
- 抖音“连接抖音”采用已保存设置，启用并打开专用登录浏览器；自动检查登录及账号状态，不再暴露“打开登录/检查登录/验证账号”三个重复主按钮。浏览器/Python 等必要配置放设置页，修改后“保存并连接”。登录需要可见浏览器，不能被无窗口选项阻挡。
- 已设置账号时验证必须匹配，不能自动覆盖绑定。首次绑定可取本次显式连接后受控浏览器实际登录的稳定账号，只有登录证据充分且配置版本/取消仍有效时保存，不能根据昵称猜测。保留修改绑定的显式设置入口。
- 断开连接保留配置和登录数据，不自动重新启用；“退出登录”若保留则清楚区分会清除平台登录凭据。
- 搜索、观看、任务取消、结果/失败提示及 QQ 分享保留；抖音审批和不支持能力的限制保持。分享 QQ 的按钮应与已存在的直接发送行为一致，不误称申请。

## 功能需求
启用/登录/核验的编排属于对应 Runtime 服务，不依赖页面存活。异步操作绑定配置版本和连接意图，取消、停用、配置修改、账号变化与 Runtime 关闭后迟到结果不能恢复连接/覆盖配置。重入有界，失败不伪造已连接；轮询不覆盖编辑草稿，页签切换保留本页未保存的输入。

## 边界条件
缺依赖、首次无凭据、既有凭据有效/失效、二维码过期、账号不匹配、无窗口模式登录、取消/重复操作、页面离开、停服、380px 窄屏。

## 技术约束
沿用现有模块、beUI、浏览器租约/队列、上游验证和权限门。不更改公共 API 的现有含义，可加认证连接编排接口。新增职责明确的局部模块可行，不建立新包。没有 schema 迁移或新外部依赖。

## 兼容性要求
保留旧 CLI/API、B站匿名读取、抖音审批/请求门与账号匹配；共享 QQ 折叠样式已修复，不重复改通用组件。

## 验收标准
- [x] B站可一次操作进入核验/扫码，成功后直接可用，无第二次启用。
- [x] 抖音可一次操作保存必要配置并打开登录，自动检查状态；已有绑定不会被换号覆盖。
- [x] 取消/停用/配置变化/停服阻止迟到启用、迟到凭据写入及资源泄漏。
- [x] 两页常用功能为清楚分组/页签，草稿保留，桌面/380px 无明显错位。
- [x] 既有观看、匿名读取、分享/审批行为与边界保持，文案不误导。
- [x] 风险相称的定向检查、隔离实际组件 UI 和独立验收通过。

## 待确认问题
无；范围为上一阶段体验在已有两个连接上的一致化，外部平台权限不扩张。
