# Spec 008: P6 跨平台安装、运行与数据迁移

状态：原三项返工独立PASS并提交a0e8f61。后续跨系统迁移发现的共用stop提前返回已修复并获新的独立PASS；当前Mac/Linux arm64产物无绕行完成运行中直接备份/恢复及往返数据、记忆、凭据与恢复失权验证。Windows、真实云账号、跨schema及正式发行等未验项继续单列。

## 背景

开发者能运行源码不等于普通用户可以安装软件。产品需要 Windows/macOS Desktop、Linux CLI/Headless、Docker/systemd，以及同一条鱼的数据备份、恢复和升级路径。

## 目标

交付不要求普通桌面用户自行配置开发工具的安装产物；Linux 可以纯 CLI 长期运行。安装目录与数据隔离，窗口关闭/托盘/后台策略明确，升级可校验，用户可真实备份、恢复并迁移人格、记忆与经历。

## 非目标

不以源码构建说明代替安装验证，不以未执行的 CI 声称跨平台支持，不伪造已发布的下载链接或签名。没有用户授权不创建云资源、发布release、推送代码或购买签名服务，不用本机其他应用的签名密钥。

## 当前行为

P0–P5已有Runtime/CLI、Tauri入口、DSH/人格/记忆/平台适配与活动，本地代码返工通过独立验收；P1正式Linux镜像有真实DSH运行证据，Windows仍缺。桌面当前依赖开发者启动Runtime，bundle关闭且build使用--no-bundle。尚未具备独立安装、更新、备份恢复和systemd交付；平台未实现协议与账号验证限制继续保留。

## 目标行为

Windows/macOS 用户安装后通过向导配置并启动同一 Runtime，关闭窗口按设置保持后台，托盘能打开/暂停/退出。Linux 用户安装后通过 CLI 或 systemd/Docker 运行。升级与恢复前校验兼容性和完整性，失败不损坏已有鱼的数据。

## 功能需求

1. Windows/macOS Tauri 产物包含所需 Runtime、Node及应用资源，明确各架构和可选平台插件依赖。首次启动向导完成数据目录、模型/人格、后台行为等真实设置；缺失外部辅助服务可诊断，不能把依赖缺失隐藏为已安装成功。
2. Desktop 启停通过统一 Runtime 管理；已有实例复用，避免双实例和无关进程误杀。关闭窗口、最小化、托盘和退出有一致含义；后台运行及开机启动由用户配置，停用后有效撤销。
3. Linux 提供可验证安装路径、实际 CLI 可执行入口与 Headless 模式，记录 Node/系统依赖或随发行包提供它们；`onboard/config/doctor` 真正处理配置和诊断，不能只是帮助文本或静态成功输出。
4. systemd unit、安装/卸载步骤、环境配置、用户/目录权限、停止超时和日志可用；Dockerfile/Compose 有非root运行、持久数据卷、健康检查和明确管理入口。只有满足认证/TLS条件才允许远程管理，不能为容器使用而裸露管理API。
5. Backup 导出用户选择的人格、模型非敏感配置、会话、记忆、日记、经历和插件配置，具有版本、schema、文件清单与校验。数据库使用一致快照，不能复制不一致的WAL主文件；默认排除密钥、Cookie和浏览器会话。
6. 用户明确选择包含凭据时，必须通过独立口令/密钥加密保护并标注可迁移范围；不得把仅本机可解密的密文当作已迁移凭据。默认恢复后需要重新配置的模型/账号准确显示未配置状态。
7. Restore 在暂存目录验证归档结构、大小、路径、校验、版本和schema，拒绝路径穿越、链接逃逸、过新schema与损坏数据。协调Runtime停用/独占，采用可回滚替换；失败保留原数据并有明确错误，不能自动删除用户原目录。
8. 在另一独立数据目录实际恢复并启动，确认同一人格、会话、长期记忆、日记与活动保持；不同操作系统的数据路径和本机运行信息不能从旧系统盲目搬入。连接token、PID和临时锁重新生成。
9. 提供真实更新检查、下载/完整性及签名校验、兼容判断、安装和失败回退路径；离线或无release时准确显示。更新源与信任配置明确，拒绝无可信校验或错误签名的可执行产物。Tauri与CLI更新不能绕过用户配置或静默回退到不安全传输。
10. CI 生成各目标真实产物与校验元数据；实际签名、公证和release发布需要用户提供凭据/授权，未具备时只报告未签名本地测试产物。安装/升级/卸载/后台保持与数据不丢失按系统分别验证。
11. 文档覆盖安装、首次设置、可选插件依赖、CLI/Headless/Docker/systemd、备份恢复、升级回滚、数据迁移与安全限制；命令和下载入口均与实际产物一致。

## 边界条件

无开发工具的干净环境、路径空格/非ASCII、已有Runtime、窗口关闭、系统重启、权限不足、只读卷、磁盘不足、损坏备份、过新schema、归档穿越、错误口令、下载中断、签名不符、升级中断、恢复后凭据缺失、不同平台路径和卸载保留数据。

## 技术约束

保持 Tauri/Node/TypeScript 和单根工程；平台原生封装不复制核心业务。用户数据与安装目录分离。系统服务安装/启动和测试只操作明确的本任务实例，不能修改其他服务或全局凭据。发布、签名和Git写操作按已有授权边界。

## 兼容性要求

已有数据版本可受控向前迁移且失败可恢复。插件和辅助服务兼容性检查独立，缺一个平台插件不阻止基础产品启动。支持列表以各系统真实构建、安装和运行记录为据。
