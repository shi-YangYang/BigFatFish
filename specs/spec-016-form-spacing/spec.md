# Spec：收紧产品表单间距

## 背景
用户先要求本地commit，再要求产品UI收紧，明确表单元素margin，解决松散、不精致的观感。上一阶段已提交8b4bbd8，本轮开始dev工作区干净，不创建空提交。当前Done，新独立验收PASS；沿用beUI、DS蓝、紧凑桌面WebUI。

## 目标
通过明确的间距层级，让模型配置、通用/数据设置、人格和平台表单的标签、输入、说明、分组与操作区排列一致、紧凑而可读。

## 非目标
不新增功能、不改交互/状态/请求/权限，不重构信息架构、组件库或依赖，不改导航/聊天布局，不重打发行包或恢复旧P0–P7任务。

## 当前行为
Desktop与Web从入口共用style.css。form/fieldset/settings的20px gap、p的12px上下margin、Disclosure的16px外margin与16px内padding、卡片gap与子段落margin相互叠加。Models的说明和状态作为独立行产生额外空隙，高级区与主操作缺少稳定节奏。

## 目标行为
- 标签与控件6px；字段行与双列网格16px；分组24px；同行按钮8px；字段说明与控件6px，状态与所属动作8px。
- 页面内容内边距桌面24px、窄屏16px；表单卡片内边距16px。保留现有宽度、40px控件、字号可读性与蓝色主题。
- 同一层只由父级gap或明确块间margin负责间距，不叠加段落/表单/折叠默认margin；长说明可换行，提示和错误仍完整可见。
- 模型诊断、推理设置、折叠高级与保存区形成清晰的近邻关系；保持DOM顺序、可访问名称、事件和数据所有权。

## 功能需求
1. 在现有共享样式中集中定义实际采用的间距token，修改旧规则而非追加一层覆盖补丁。
2. 优先纯CSS；只允许为字段说明或操作反馈建立必要的普通语义布局容器/class，不修改业务逻辑或beUI底层交互。
3. 应用到直接使用共享Field/FormGrid/ActionRow/Disclosure/Card的表单区域；检查模型、通用/数据、人格与平台表单同根因路径。聊天/导航保持现有节奏。
4. 宽屏两列底边对齐，380px单列与按钮换行正常，焦点/错误不裁切；不靠隐藏内容实现收紧。

## 边界条件
长说明、成功/错误反馈、展开高级区、双列表单、checkbox、卡片内表单、380px窄屏。

## 技术约束
保持原目录和普通源码模块，无新增依赖；不在每个调用点复制margin规则。不为纯展示调整升级验证规模。

## 兼容性要求
Desktop/Web共享样式同步生效。原输入、保存、诊断、折叠、焦点及40px控件契约不变；不访问真实账号。

## 验收标准
- [x] 统一间距token及父级间距职责；清除表单内叠加margin。
- [x] 代表表单（模型含高级/反馈、通用或数据、人格或平台）桌面与380px视觉紧凑、对齐且可读；提供实际生产组件隔离数据截图。
- [x] diff仅包含样式与必要展示分组，业务/请求/依赖未改变。
- [x] 新独立验收PASS，文档记录真实证据，按持续授权本地commit。

## 待确认问题
无。用户已明确目标和方向；间距数值为范围内可逆设计细节。
