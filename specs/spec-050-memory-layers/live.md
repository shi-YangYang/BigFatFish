# 真实模型对话验证

2026-11-07，macOS，时区 Asia/Shanghai。使用本机已配置的阿里云百炼 Token Plan 聊天模型 `deepseek-v4.1-flash`，通过正式 Runtime 的 HTTP 聊天接口和 DSH 发起请求。只取所选模型配置和密钥，在独立临时目录内使用合成对话；真实用户库以只读方式打开。未使用模拟模型、历史账号对话或 QQ 实发。语义索引关闭，检查默认配置下的召回。

## 修复前

原话「我养了一只叫橘团的猫。」已成为有出处的事实。「我是男生，今年23岁；我周六约好了体检。」产生了体检记录和一条未拆分的男生自述。将体检改为周日，停掉 Runtime，重开后在新的空会话询问年龄、性别、小猫名字和体检日期，云端只答出了周日。期间四条消息及后台任务均成功，入库并不等于能在新会话取回。

第一次接入人物资料后，相同输入的资料查询仍为空。实际输出定位到带分号的自述和「刚刚说错了」这样的更正前缀。修复后的试跑还发现凌晨的资料日期提前一天；来源日期已改用 Runtime 本地日历日。

## 最终测试

从一个空的 schema 11 数据库开始。每轮先等聊天回复结束，再检查对应队列任务和来源行。第 3 轮完成后停止 Runtime，使用同一数据库重新启动，并通过接口创建全新会话。以下时间是提交消息到观察到完整回复的时间，不是性能基准。

| 轮次 | 实际发送 | 原话、记忆和资料 | 回复耗时 |
| --- | --- | --- | --- |
| 1 | 我养了一只叫橘团的猫。 | 原句落库，后台整理后得到主题「橘团」的宠物事实，提取证据与原话相同。 | 7.14 秒 |
| 2 | 我是男生，今年23岁；我周六约好了体检。 | 一条原消息，体检、年龄和性别三个有来源的事实。资料接口返回「男」「23 岁」，来源日期为本地 11 月 7 日。 | 3.56 秒 |
| 3 | 刚刚说错了，我今年24岁。我的体检改到周日了。 | 人物资料变为「男」「24 岁」。年龄保留第 2、3 轮引文；体检的当前日期为周日，保留原预约与改期两条证据。 | 3.05 秒 |
| 4 | 你还记得我的年龄、性别、小猫名字，以及体检是星期几吗？请只用一句话回答。 | 重启后的新会话通过云端模型返回下方原答。 | 2.04 秒 |

> 你今年 24 岁，是男生，小猫叫橘团，体检改到周日啦。

最终库保留四条用户原话、四条已记住的重要事实和两项人物资料。四项后台任务均为 `done`，失败次数均为零。真实回复与数据库、管理 API 的结果分别核对。真实测试中的模型凭据已从隔离库清除。

使用上述真实测试库启动 WebUI，在 Chrome 里从「我的鱼 → 记忆 → 人物资料」看到“男”和“24 岁”，两项日期均为 2026-11-07。打开年龄的来源，界面显示对应的完整聊天原文。验证结束后已删除临时数据目录。

## 资料归属返工的云端验证

在另一个空数据库内，连续向同一个真实模型发送「男，23岁。」「说一下我妹妹的情况。女，19岁。」「下面聊聊我弟弟，你先问我他今年多大。」。模型实际追问「弟弟今年多大呀？」，下一条只回答「17岁。」。逐轮读取资料都只有本人的男、23 岁，妹妹的 19 岁和弟弟的 17 岁没有替换其中任何一项。再开一个空会话询问本人，云端回答「记得呀，你是男生，记录里是23岁。」。五条原始输入独立落库，五项队列任务均完成，无重试。聊天回复中模型对家人的口头确认与实际长期存储分开核对。

这次实测还发现「下面聊聊我弟弟，你先问我他今年多大。」一度被当成重要事实保存。核对人物资料通过，但查看第二层才发现这一处误收。

修复后，仅在新库重发该原句。真实回复为「好呀，那先从弟弟聊起。他今年多大了？」。原话完整保存，后台任务完成且未重试；重要事项和人物资料均为零条。此次云端复验的临时数据库与测试凭据已清除。
