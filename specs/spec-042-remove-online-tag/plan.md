# 实施与验证

先移除 App 顶栏状态菜单及其活动轮询，保留连接健康检查。复用当前活动计划和 Web 通用设置承载原操作，清理对应专用 CSS，并迁移依赖原入口的直接相关用例。

修改涉及共享外壳与两个操作入口，按 S2 仅检查相关界面。优先运行覆盖 Desktop/Web 的既有 platform-direct-ui 用例，无需全量构建。独立验收审阅差异及该检查结果。

## 实施报告

共享 App 的顶栏已移除状态按钮、圆点、浮层及专用样式。外壳每 4 秒只查询服务状态。初次连接失败页和已连接后掉线的横幅继续提供重新连接。活动页读取状态后即可暂停或恢复，包括没有任务和计划时。Web 通用设置调用原退出接口，数据页不展示该按钮。抖音说明同步更新了活动控制路径。

S2 定向检查 `./node_modules/.bin/vitest run tests/integration/platform-direct-ui.test.ts` 通过，两种宿主共 2 项，耗时 4.48 秒。Chrome 加载 Desktop 和 Web 各自的 Vite 入口，使用隔离的 IPC/HTTP 夹具，检查了 900px 顶栏、380px 新对话及导航、空闲暂停与恢复、直接互动，以及 Web 通用设置退出后回到登录页。desktop-webui 的顶栏断言及 desktop-usability 的活动和独立浮层样例已更新，仅审阅差异。未执行全量检查、原生打包或真实服务重启。
