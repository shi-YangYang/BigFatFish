# Spec 031：QQ 消息错误诊断与准确反馈

状态：Done；独立验收PASS，见acceptance.md。

## 背景
用户报告 QQ 连接消息记录中有消息像被拒绝，明确要求排查错误并修正易误解处。dev 基线06b9c7e，开始干净。当前实际数据有5条sent、1条blocked/MODEL_RUN_FAILED；失败时间2026-11-05 09:35（Asia/Shanghai）。对应DSH结束原因为error、code SERVER、message 502 {}。当时转发层既会透传上游HTTP状态，也会将网络异常变成502，因此旧记录无法再区分具体来源。

## 目标
在不暴露凭据或响应正文的前提下保留模型失败类别；QQ记录明确区别生成失败、发送前阻止、协议拒绝、交付未知和中断，并提供简短可理解原因。

## 非目标
不重发历史消息、不自动重试付费模型或QQ发送、不改变好友/群/主人与审批权限、不改模型地址或密钥、不重写连接流程，不做数据库迁移或全局UI翻新。不声称已修复或确定历史外部502根因。

## 当前行为
模型转发丢弃错误正文以保护密钥，但同时丢失可安全保留的HTTP/网络分类。DSH非正常turn/end统一MODEL_RUN_FAILED。Channels.reply将生成失败、取消等均记为blocked。最近消息只显示状态和时间、忽略error且只加载一次；主动发送另有重复映射且忽略error，操作记录直接展示内部事件串。桌面聊天同源错误缺少部分中文映射。

## 目标行为
模型HTTP失败、网络/传输失败、超时、空结果及未知运行失败在已有错误链保留安全分类；HTTP类别仅按实际观测，不从任意错误正文猜测或泄露内容。QQ显示实际失败阶段和简短原因，已有blocked+生成错误也能正确展示，无需重写历史。

## 功能需求
- 在模型转发/DSH职责层传递受限错误码或受限元数据，经现有Chat错误字段到QQ；不会被泛化catch再次抹掉，也不把取消改成网络错误。成功不受前次失败诊断污染。
- 生成异常使用失败语义，权限/记忆撤回等发送前限制保持阻止；取消/重启以中断语义呈现。结果未知继续明确需去QQ核实，不自动重发。
- 自动回复与主动消息记录统一语义和原因映射；显示必要目标/时间，自动回复记录不重复混入主动发送。记录在页面停留时更新，卸载后停止，不出现旧异步响应覆盖新状态。
- 主动发送反馈按明确状态/失败请求表达，不能把确定拒绝一律说成结果未知；真正请求中断仍保持交付不确定提示。
- 操作记录用简短中文呈现已知事件，未知/旧事件给诚实的通用名称，不直接把内部事件码和复合ID当正文。
- MODEL_RUN_FAILED、EMPTY_MODEL_RESPONSE及本次新增安全模型错误在共用errorText内有中文提示，桌面聊天同步受益。必要错误提示保留，避免常驻解释小作文。

## 边界条件
旧blocked模型错误、HTTP502/401/429、连接失败、流中断、取消、生成完成但尚未发送时撤权、协议明确拒绝、协议超时未知、未知错误码、页面切换/轮询、380px长原因换行。

## 技术约束
沿用Runtime、现有错误列/接口和beUI。少量共享纯展示逻辑或组件可封装为源码模块，不分包；不得以UI特判掩盖新记录后端错误阶段。模型密钥、供应商错误正文、请求内容不进入错误信息或日志。保持流式传输、取消及最终授权检查。

## 兼容性要求
既有记录无需迁移；CLI/API现有字段结构保持。细化错误码不改变成功语义；旧通用码仍可显示，不能伪造旧502的具体来源。
