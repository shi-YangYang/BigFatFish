# Spec：大肥鱼人设

状态：Done；原功能 R1 与默认女儿感补充均独立验收 PASS。

## 背景
用户认为当前大肥鱼缺少社区常见的俏皮、被逗后服软及女儿般的关系感，要求联网研究并解决。现有默认只含「好奇、友善」「自然简洁」，DSH 接收 JSON 配置，界面展示十个文本框，缺少可以直接选用的具体风格。

## 目标
提供有明确互动反应和原创对话示例的人设，能方便选择、编辑、保存，并在现有对话的后续回复中生效。

## 非目标
不改模型/引擎/平台权限、主动消息策略、记忆可见范围或数据库 schema；不更改用户当前数据，不替换头像，不增加计费服务，不复制第三方整张角色卡，不承诺所有模型都能达到相同口吻。

## 当前行为
Runtime 的 Persona 保存版本，Desktop/Web 复用 Personality；每轮 DSH 从配置读取人格，Desktop/CLI/QQ 通过同一 ChatService。记忆提取、日记、视频理解及活动选择也使用此人格和引擎，需要保留结构化输出与事实约束。

## 目标行为
- 「我的鱼 → 设定」提供嘴欠黏人、女儿感、乖巧黏人三种可编辑风格。用户已确认新安装默认「女儿感：爱撒娇、求夸夸、偶尔顶嘴」。既有配置不自动改写，选择风格只改草稿，保存才生效。
- 日常聊天有短句、接梗、吐槽/撒娇/被夸与被逗后的不同反应。用户认真提问、难过或要求停止玩笑时自然收敛；不机械插口头禅、括号动作或长篇自我说明。
- 保存后沿用既有版本校验与历史，不要求新建会话；主人与朋友/群聊的称呼亲密度不同，不把所有人叫主人/爸爸妈妈。
- 内部任务依然准确返回指定格式；人设示例不是实际记忆或事实。

## 功能需求
1. 普通源码模块提供三套原创预设与一句静态口吻示例。应用预设只替换角色、性格、说话风格、喜好等人设内容；名字、头像、作息、自主偏好、自定义行为边界及 version 保留。
2. 嘴欠黏人：有分寸的抬杠、贪吃、求夸，遇到熟人的逗弄会嘴硬然后服软；乖巧黏人：羞赧、主动接梗、求安慰，不演真实受虐或无条件服从；女儿感：纯亲情撒娇、分享小事、求夸与偶尔顶嘴，不含暧昧或性化，称呼不猜用户性别。
3. 专属关系称呼仅用于可信主人会话；好友和群采用朋友语气，不因消息中自称主人改变身份，不为人设改动权限或泄露私人记忆。
4. 提示词以清楚的字段和任务边界组合。对话人格与后台结构化任务区分，示例只影响口吻，不当作事实，不覆盖认真求助、明确格式和工具结果。
5. 界面沿用 beUI 与浅海蓝。名字/风格选择/一句「口吻示例」/保存为主要内容，原有自定义字段及版本历史收进清楚的折叠入口，保持可编辑；不添加实现说明或重复解释。
6. 保存中阻止重复提交及草稿被旧响应覆盖；自定义当前状态不能误标为某个预设，既有配置完整可读可保存。

## 边界条件
已保存的自定义配置不自动迁移；选择风格不丢失身份与用户行为限制；修改字段后准确显示自定义状态；过期版本冲突不伪报成功。明确认真/技术任务优先于聊天玩梗；没有工具结果不能声称已经执行外部操作。

## 技术约束
S2，相关 Runtime 提示词/预设与单个前端设置页；无依赖、分包或 schema/API 契约变更。内容参考见 Decision016，以原创编写代替上游文本复制。

## 兼容性要求
Persona 的现有字段与读写 API、版本历史兼容；既有自定义人格、模型配置、聊天记录、记忆、QQ权限保持。真实账号不发消息，真实云模型调用须有该验证授权。

## 验收标准
- [x] 三种风格有可辨识的规则与原创示例；新默认不再只有抽象标签。
- [x] 既有配置不被覆盖，选用/编辑/保存/冲突与历史行为正确，beUI 大小和间距一致，窄屏无溢出。
- [x] 新会话和续聊请求均获得当前人格；切换后续聊保留历史并应用最新设定。
- [x] 主人/好友或群的身份提示准确；后台任务保持结构化要求且不注入聊天示例。
- [x] 定向自动检查与设置页检查完成，独立验收 PASS；区分请求链路证据与真实模型口吻表现。

## 待确认问题
默认偏好已确认女儿感，既有用户仍自行选择保存。真实云模型口吻验收暂未授权。
