# Spec：收紧 QQ 回复设置

状态：Done；2026-11-04，独立验收 PASS。

## 背景
用户确认 QQ 已能正常回复，但指出回复设置布局凌乱。当前账号选择、手动输入、复选框、多层折叠和记录入口纵向散落，缺少明确分组。

## 目标
把回复设置整理为紧凑、对齐、层级清楚的一块表单；消息与审批记录形成独立分组。

## 非目标
不修改 QQ 连接、轮询、保存/撤权、联系人加载和审批逻辑，不操作用户真实账号或重启后台，不改其他页面的全局样式。

## 当前行为
「手动输入 QQ 号」独占一行，主动消息只有一个开关却单独折叠；表单和底部记录均没有统一容器，默认标题/段落/折叠间距叠加。

## 目标行为
回复设置集中在同一简洁卡片内，账号选择和手动输入在同一行；自动回复、群聊范围与主动消息权限清晰排布，保存/暂停在固定底部操作区。减少不必要的折叠；记录入口集中在表单外，明确区分权限设置和实际发送/记录。

## 功能需求
- 继续使用现有 beUI 组件与浅海蓝，40px 常规控件、紧凑间距及统一左右边线。
- 主人选择/手填、群选择/手填、主动审批开关、保存/暂停、既有服务与记录均可达，原始回调和状态保持。
- 桌面布局紧凑；380px 下无横向溢出、标签遮挡或按钮重叠；长昵称正常截断或换行。
- 设置与记录不再表现为同一串散落的折叠标题。

## 边界条件
好友列表为空、手填模式、群列表为空/展开、已连接/未启用、窄屏与长昵称。

## 技术约束
仅调整 QQ 页面布局、文案和局部样式；如需要组合组件，可增加展示 slot，不复制业务逻辑、不拆包、不增加依赖。

## 兼容性要求
所有接口、请求内容、草稿保护、禁用态和实际授权行为保持。

## 验收标准
- [x] 账号选择与手动输入紧凑排列，设置完整收纳于单一容器。
- [x] 权限层级、底部操作、消息与审批记录清晰，无冗余单开关折叠。
- [x] 桌面和380px窄屏目视通过，字段/按钮对齐，保留所有原行为。
- [x] 差异仅涉及本次 UI 展示，经独立验收。

## 待确认问题
无。用户明确要求修正当前布局，沿用现有产品与组件方向；每阶段本地 commit 授权持续。
