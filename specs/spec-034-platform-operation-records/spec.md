# Spec 034：精简视频平台手动观看与记录

状态：Done；独立验收PASS，见acceptance.md。

## 背景
用户要求将QQ消息页精简同步到B站和抖音，经澄清明确「删除手动观看这种，分享这种还是要保留」。dev基线0ae89c3、工作区干净。

## 目标
删除连接页中的手动搜索/观看入口，记录区精简为操作记录，同时保留现有分享与互动能力。

## 非目标
不删除后台观看、搜索、计划/自主活动、CLI/API、持久化或历史数据；不关闭社交能力、不改变抖音审批/权限，不实现目前尚不支持的抖音分享协议。不重做我的鱼任务页和全局审批界面。

## 当前行为
B站有观看、记录、设置页签，记录内含冗长观看详情及分享到QQ。抖音有观看、互动、记录、设置，记录复用详细任务组件并可选择视频返回观看。B站无独立audit接口；两平台均已有真实持久化任务及状态可供记录展示。

## 目标行为
B站默认操作记录（记录/设置），抖音默认操作记录（记录/互动/设置），连接卡片和设置保留。各记录页只有一个操作记录卡片，以真实任务的动作/视频标题或标识、状态、创建时间及必要失败原因形成紧凑列表，内部滚动。保留记录相关必要操作，但不展示整段总结、字幕/采样元数据、搜索结果、评论全文或内部任务载荷。

## 功能需求
- 删除B站搜索/BV手动观看表单与请求状态、抖音搜索/推荐/详情/评论读取/手动观看表单与请求状态；删除观看页签及返回观看的回调。
- 保留B站已有视频的「分享到QQ」和选择分享对象能力，继续调用既有share接口并准确区分已发送/失败/未知；不因精简记录而失去分享入口。
- 保留抖音既有点赞/评论表单和审批入口，以及全局审批使用的组件；不打开原先隐藏且协议未支持的私信/分享/投稿。视频ID仍供互动目标填写。
- 记录以现有任务数据为事实来源，不伪造连接/分享成功或新audit事件。失败原因用现有安全中文映射，长内容换行，活动中取消可保留。
- 新的紧凑记录展示只用于连接页；共享任务页的详细ActivityRows保持原职责，可清理已无调用的onVideo选择回调。
- 记录自动更新、空态与读取失败恢复保留；记录错误不能让已读取的连接卡片永久加载。连接/设置/分享/互动的在途保护和未保存草稿规则保持。
- 直接关联文档及旧UI测试中已删除的入口同步，保留后台能力验证。

## 边界条件
零记录、只有失败/运行中记录、已有已理解可分享视频、分享对象未填/发送未知、抖音互动视频ID、轮询迟到/离页、长标题及窄屏；无新真实平台操作。

## 技术约束
沿用现有React/beUI/ContentScroll，前端源码层复用紧凑记录布局即可，不增加API、schema或依赖。当前后台任务列表足以支持目标记录，不新建持久化审计系统。

## 兼容性要求
历史数据、计划与CLI完整保留；B站分享与抖音审批仍走原后端边界；Desktop/Web共用界面。

## 验收标准
- [x] 两连接页不再有手动搜索/观看入口或其请求/状态；默认进入操作记录。
- [x] 两平台记录简洁、真实、内部滚动，长结果不再逐卡展开；空态/失败恢复明确。
- [x] B站分享可达且反馈准确；抖音已有互动和全局审批完整保留。
- [x] 后端/数据/计划未改，直接文档及失效测试入口同步。
- [x] 相关类型检查和独立差异验收通过。

## 待确认问题
无；用户已明确移除手动观看类操作并保留分享类能力。
