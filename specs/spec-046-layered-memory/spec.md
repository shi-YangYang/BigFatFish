# Spec 046：一条鱼的分层记忆

## 背景与当前行为
本机和 QQ 主人私聊已有账号身份、确认记忆检索和模型可选用的会话笔记。群聊的权限受众同时被用作称呼依据，无法区分主人在群发言与普通群友。确认记忆按提问词命中；单次对话里说过的偏好不保证在新会话里出现。B站与抖音会写观看事件和候选兴趣，但视频理解与聊天没有稳定的经历召回路径。

## 目标与目标行为
让大肥鱼分清「谁在跟我说话」「我和这个人之间的习惯」「我自己做过什么」。参考[腾讯云 Agent Memory 的分层与溯源设计](https://cloud.tencent.com/document/product/1813/132100)，在本地构建可单独验证的记忆写入、组织和读取，不引入云服务。

## 功能需求
- 原始记录：沿用有身份的消息、当前场景笔记、实际观看事件作为证据；分层索引或结论应能指向具体来源。
- 单条事实：按既有规则管理有来源的事实、偏好、候选；模型推测不能自行变成主人的稳定事实。
- 场景与经历：按当前话题、入口、作用域组合相关材料，支持近期/按话题回想自己的真实 B站、抖音经历，以及只属于当前聊天的笔记。聚合与检索有预算。
- 核心关系与画像：发言人身份与受众权限独立；私下对话不靠当前提问重复命中关键词也能使用有限的稳定偏好。修改或忘记可管理的记忆后，新会话中不再引用旧结论。
- 自主选片和视频理解区分真实观看证据与参考记忆；鱼看过视频不等于主人喜欢，外部标题、账号或评论不能确立主人身份。

## 非目标与技术约束
不接腾讯云、不引入付费向量数据库、不开另一套大脑、不新增平台私信，不将平台消息同步到桌面聊天列表。优先沿用当前 SQLite、管理界面、聊天模型和权限；不隐式重放全部历史或为每条消息追加模型调用。

## 边界与兼容
本机主人、绑定 QQ 私聊、群中主人、普通群友、冒称主人的人需明确区分。群/朋友不读主人私有资料、其他聊天或私人观看历史。保留权限撤销、原始证据、用户编辑删除、备份恢复与旧客户端的现有边界。

## 验收标准
- [x] 可信主人关系独立于昵称、消息文本及检索相关度；权限检查以真实受众为准。
- [x] 通过隔离模型适配器输入与本地模型服务夹具验证新会话回想、场景隔离、视频经历召回、推断非事实及来源关联。
- [x] 偏好的沉淀、纠正和遗忘符合用户选择；无额外云依赖、默认批量回填或真实平台写操作。见[独立验收](acceptance-r1.md)。

## 待确认问题
无。用户明确：群内认得绑定的主人，不透露私聊或桌面的私人记忆；重点是如何指定、识别主人，不是让大肥鱼猜测。主人由「连接 → QQ → 回复设置 → 主人 QQ」指定。偏好沿用保守边界：在主人私下直接委托记住、指定称呼是明确指示；普通自述可沉淀为候选，推测不能直接确认。用户仍可在记忆页编辑、确认或删除。
