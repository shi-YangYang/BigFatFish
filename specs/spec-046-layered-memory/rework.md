# 首轮返工

1. 原主人换绑后作为普通好友，历史主人笔记不得出现在自动召回或工具结果中，且不能被好友读、删或错误去重。按授权角色和原消息的可信出处识别旧私聊笔记，保留对相应身份可见的旧记录、不批量改真实数据。群话题仍允许在本群成员间共享群内笔记。
2. 群和好友正常切换话题（同样包括单条已公开事实命中与不命中）不能清空短期会话。区分「这一轮选给模型看什么」与「以前可见的内容现在还能不能用」；保留撤销共享/更换身份使旧会话及在途回复失效的边界。覆盖真实 engine session ID 和 resume 标记，模拟换绑及工具读、删，复用上轮无影响的验证。

## 实施记录
- `NoteScope` 统一笔记读写边界：机器人/私聊账号的原范围加上入站时记录的可信作者（主人或好友），原表及仅记忆备份可直接使用。群内仍按群共享。自动召回、工具查询/删除与重复检查使用相同的角色隔离。
- `PublicMemorySession` 在现有 engine 会话状态里保存共享授权指纹、模型曾接收的笔记 ID；随问题变化的匹配结果不再是权限指纹。未公开到该会话的新笔记不会阻断回复；已披露笔记被删或撤销共享时，阻断在途回复，下一轮重新开始。
- S3：针对性 Vitest 筛选运行 layered-memory、qq-rework、source-persona-tools 三个相关用例，3 项通过（另外 4 项无关用例未选）。观察了换绑后的实际 OneBot 输入、工具查询/删除结果、两轮模型输入的 sessionId/resume、暂停发送时删除已披露笔记后的拦截及随后的会话恢复。生产 `tsc -p tsconfig.node.json --noEmit`、diff 空白检查通过。仅临时数据与模拟服务。
