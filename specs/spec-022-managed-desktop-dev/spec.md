# Spec：开发入口统一管理进程

状态：Done（返工独立验收 PASS）；2026-11-04。

## 背景
用户启动新版桌面后仍复用了长期存活的旧 Runtime，普通接口正常而 `/v1/events/stream` 返回 404。现有 `desktop:dev` 仅运行 Tauri/Vite，后台由桌面调用 CLI 以 detached 模式启动，不随开发命令退出。用户要求一条开发命令统一管理进程，并明确选择继续使用当前配置和聊天记录、接管本项目启动的旧后台。

## 目标
`npm run desktop:dev` 负责最新源码后台、前端开发服务和原生桌面的启动及清理，消除新版桌面复用旧后台的问题。

## 非目标
不改正式安装版后台常驻行为，不迁移/清空数据，不引入新包管理或外部进程管理依赖，不实现无关的发布/更新改造。不承诺无法捕获的系统强杀能执行全部清理；不默认增加 Runtime 源码热重载。

## 当前行为
- `desktop:dev` → Tauri dev → Vite，Rust setup 调用发行资源 CLI start，已运行后台被直接复用。
- 仅重新编译桌面不会刷新或重启 Node 后台；Ctrl+C 后后台可能仍然存活。
- 桌面记住的数据目录可以覆盖环境路径，开发与正式应用生命周期未分开。

## 目标行为
- 启动先准备当前 Node 源码；沿用既有桌面设置的数据目录，显式开发 data-dir 覆盖应在所有层一致。
- 针对目标数据目录，识别并优雅停止本项目此前启动的后台，再运行本次受管理的 Runtime，完成认证就绪校验后启动桌面。
- 本次开发命令拥有 Runtime/Vite/Tauri 的生命周期；Ctrl+C、原生退出、启动失败或关键子进程异常时清理自己的进程。正常桌面关闭在托管开发模式退出整套开发会话，正式安装版仍遵循原设置。
- 原生代码热重载期间不会再次生成 detached 后台；每次重新执行开发入口都会使用当前后端源码。
- 其他项目/安装版或身份无法确认的后台不自动终止，清楚提示冲突；避免两个开发命令同时接管同一实例。

## 功能需求
1. 保留用户现有模型配置、聊天记录和设置；不复制密钥或写入日志。
2. 使用现有 Runtime 认证请求、实例身份与锁语义完成就绪和优雅停机；不以删连接文件、模糊进程名或全局杀 node/tauri 替代。
3. 与正式模式显式隔离；托管开发启动不再运行旧 portable Runtime，维护等原生 CLI 调用使用当前开发代码。
4. 标准命令跨 macOS/Windows/Linux 可用；保留合理 Tauri 参数透传，不靠 Unix 专属 shell 命令实现主流程。
5. 出错返回非零并说明哪个步骤失败；启动或清理失败不得伪报成功。
6. README 更新为一条开发命令，说明使用现有数据、退出行为、后端改动重新运行及外部后台冲突。
7. 托管开发的原生入口在任何停机/写入前拒绝备份导出、恢复、安装更新及应用重启，并提供明确中文提示；这些操作需先结束开发会话，再通过独立 CLI 或安装版执行。只读归档检查与更新检查保留，避免停服维护被 supervisor 当成异常而杀死维护子进程。

## 边界条件
后台准备失败、前端端口占用、重复启动、Runtime 启动竞争、受管实例被替换、信号发生于启动阶段、原生热重载、后台意外退出。已知用户原后台和开发窗口仅由协调者在完成隔离验证后处理，实施/验收 Agent 不操作真实数据或用户进程。

## 技术约束
沿用 Node 24、npm、Tauri 2 和既有普通源码模块；不拆包、不改变原目录职责，不升级依赖。实现放在开发启动器和原生开发适配职责层，不用前端隐藏断连提示掩盖后台错配。

## 兼容性要求
发行包启动、关闭到后台、CLI 独立 daemon、持久化格式和现有鉴权保持。仅开发专用入口拥有受管语义，正式二进制不能意外启用开发路径。

## 验收标准

- [x] 本项目旧后台可安全接管，未知/外部后台和重复开发实例受到保护。
- [x] 正常退出、Ctrl+C、启动失败和 Runtime 异常清理受管进程，实例身份检查防止误停替代进程。
- [x] 托管原生启动/退出/热重载不另起 detached Runtime；正式模式不变。
- [x] 开发模式中的停服维护在执行前被明确拒绝，只读检查不受影响，正常模式的维护行为不变。
- [x] 定向测试覆盖实际进程边界、就绪及清理，原生相关检查通过；无 Windows 实机证据则明确限制。
