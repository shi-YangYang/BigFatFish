# Spec：收敛导航与聊天布局

## 背景
用户提供当前截图，指出左侧导航过宽、右侧两层topbar加独立会话sidebar不协调；本轮沿用已授权的简洁WebUI方向修正展示层。Done，独立验收PASS。

## 目标
将当前220px主导航+160px会话侧栏和64px+52px双顶部栏收敛为窄导航、单顶部栏、按需历史会话。聊天内容获得更大的连续空间。

## 非目标
不重新改配色/品牌、不添加功能或UI库、不重写聊天状态/API、业务表单与原生宿主，不调整目录或依赖。

## 当前行为
App固定渲染topbar，Chat另渲染chat-toolbar；宽屏会话列表常驻，主导航只含3个入口但占220px。两级容器都以边框分割，形成重复框架。

## 目标行为
- 桌面主导航约72px（不超过80px），保留大肥鱼娘识别、聊天/我的鱼/连接及底部设置；短标签或可发现提示、可访问名称与选中态清晰，去掉占位标语。
- 聊天只显示一条约56–64px的顶部栏：历史入口、当前会话标题、新对话、待审批及连接状态共同编排。不要只隐藏其中一行的文案而保留空栏。
- 历史对话默认收起，所有宽度按需打开浮层/抽屉，支持选择后关闭、Escape/关闭、焦点回到触发入口；不常驻挤压消息列。复用既有Drawer优先。
- 消息与输入框共用居中的阅读宽度与左右边缘，不因收窄导航把文字拉到全屏过宽。其他业务页沿用窄导航和唯一页顶栏。
- 小窗口可用菜单打开完整导航；标题可省略号，操作保持可达。重要审批/断连/错误信息仍保留。

## 功能需求
Chat保留挂载和既有草稿/发送请求所有权/新会话/历史选择/只读/审批错误行为；布局组合通过明确组件props或React节点，不用DOM查找移动节点、重复状态或全局事件。只让相应模块负责其布局和状态。

## 边界条件
长标题、空会话、无模型、未连接、审批提示、窄窗口和页面来回切换；隐藏Chat不得留下可操作顶栏或打开的历史对话框。

## 技术约束
沿用已有Controls、蓝色tokens、Drawer与源码模块；不分包、不增依赖；不改Runtime/数据/鉴权。普通控件尺寸保持既有约定，导航组合项可按其语义布局。

## 兼容性要求
Desktop/Web共用界面。各导航入口、模型设置、审批和本机维护保持可达；用户数据无需迁移。

## 验收标准
- [x] 1100宽主导航不超过80px，聊天只有一条可见topbar，历史默认不占布局宽度。
- [x] 历史打开/关闭/Escape/选择、新对话、主导航及返回聊天可用，草稿与已有请求/审批回归保留。
- [x] 1100×760、820×760、640×760及最窄380×500无横向溢出，顶部动作可达、发送按钮可见，消息/输入阅读边缘一致。
- [x] 检查至少聊天、历史打开、非聊天页面的实际截图；必要定向检查与独立验收通过。

## 待确认问题
无阻塞。用户已明确否决宽侧栏/双topbar/常驻会话sidebar；具体像素和组件组合为实现细节，保留所有功能入口。本阶段完成后按持续授权本地commit，不push。
