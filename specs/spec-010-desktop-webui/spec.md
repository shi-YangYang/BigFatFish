# Spec：简洁 Desktop WebUI 与大肥鱼娘形象

## 背景

用户已审阅 Decision 010 的双 Agent 产品与视觉方案，明确选择保留桌面窗口承载一套简洁 WebUI，并于 2026-11-03 要求“改”，追加联网搜索大肥鱼、将应用 icon 和鱼形标识替换为大肥鱼娘。状态：Done；实施与返工后新独立验收 PASS。此前 P0–P7 持续任务已结束。

## 目标

落实已提供的界面方案，减少一级功能曝光、统一布局与控件；使用可辨识的蓝发鲸鱼娘统一 Desktop/Web 品牌。保留既有能力及安全行为。

## 非目标

不新增包、框架、Runtime API、平台协议、麦克风录音或插件市场；不重启旧阶段验证，不配置真实账号，不推送或发布。

## 当前行为

Desktop/Web 共用 App 与 CSS。Desktop 有 17 个一级入口，聊天发送区会超出窗口，模型表单字段与操作混排；断连时 Desktop 会被首启页替换。原应用 icon 和鱼标识未使用鲸鱼娘。

## 目标行为

默认聊天；侧栏仅聊天、我的鱼、连接，底部设置。我的鱼分设定/记忆/经历/活动计划，连接按 QQ/B站/抖音展开真实能力。设置分模型、扩展、通用、数据、关于/更新与高级诊断；仅按实际宿主显示本机能力。待审批抽屉按需出现。复用原 API 和业务模块。

## 功能需求

1. 实现 Decision 010 视觉规范和层级，按普通 components/hooks 组织；UI 文案遵循 web-design。
2. 聊天历史与输入区清楚分离，输入区始终可见；首次发送可创建新会话，自动恢复最近会话；保留请求 ID、会话隔离、取消、QQ 只读和未知结果提示。无聊天模型时直达设置。
3. 上传音频转写/消息朗读在聊天可达，声音配置收进设置；没有录音能力则不显示录音承诺。
4. 保留人格、记忆候选确认、来源/共享范围、日记、任务暂停/计划、平台登录和手动操作、插件授权/调试、备份恢复、更新、日志等已有能力，在次级界面访问。
5. 审批显示既有账号、目标、正文/媒体和状态，批准一次/拒绝；不可变成无上下文的批准全部。
6. 首启和断连区分；曾经连接后断连保留当前界面/会话/输入，提供恢复，不回首启。保存配置不声称调用成功。
7. 大肥鱼娘采用已联网核实的社区蓝发鲸鳍、鲸尾、蓝白女仆 Q 版视觉；应用原生图标、品牌、聊天鱼头像和浏览器 favicon 同源。保留素材来源/生成说明，不伪称官方授权。业务功能图标继续表达动作，不把所有按钮都替成角色头像。

## 边界条件

无模型、无历史、无记忆、未登录、未配置、平台异常、断连、等待回复/审批均真实呈现；QQ 外部会话不能从本机强行发送。关键请求失败/结果未知要可见，恢复/授权风险不得因简洁隐藏。

现有会话列表不返回来源字段，不能预判某条记录是否来自 QQ；沿用服务端 `EXTERNAL_CONVERSATION_READ_ONLY` 拒绝契约，收到明确拒绝后在该会话显示只读并保留草稿。不按标题猜测、不为此改 Runtime API，也不将明确只读拒绝当成未知发送结果。

## 技术约束

沿用 React/Tauri/既有 API 适配；保持单根依赖、源码目录与数据契约。共享组件只按真实复用抽取。不读取真实鱼或其他应用凭据；可用隔离 fixture 验证 UI。视觉素材全部落到仓库，不能依赖远程热链或本机缓存路径。

## 兼容性要求

Desktop/Web 使用相同业务界面；Web 保留现有认证/退出与宿主设置差异。Native 托盘及生命周期不受导航调整影响。原有数据不迁移。

## 验收标准

- [x] 一级入口为聊天/我的鱼/连接及底部设置，默认聊天，已有能力有可达的次级入口。
- [x] 聊天新建/选择/发送/取消与草稿隔离保持，QQ 只读，语音入口真实，无模型有配置入口。
- [x] 断连不卸载聊天、清空草稿或伪装首启，首启仍可完成。
- [x] 我的鱼、平台连接、设置和上下文审批保留关键状态、风险和操作。
- [x] 统一字体/色彩/间距/控件；1100×760、820×760、640×760 无横向溢出且发送区可见，窄屏导航可开关。
- [x] 品牌、聊天头像、favicon、Tauri PNG/ICO/ICNS 使用同一大肥鱼娘；来源有记录，资源随两种前端构建可用。
- [x] 针对改动完成必要 UI 类型/构建与交互检查，独立验收通过；实际运行与受控示例验证明确区分。

## 待确认问题

无阻塞项。用户已授权方案落地和每阶段本地 commit；没有 push/发布授权。品牌按已核实的主流形象制作或使用明确许可的素材，具体来源补入 Decision 010。
