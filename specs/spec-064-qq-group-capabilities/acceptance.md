# QQ 群聊能力：独立验收

**FAIL。** 群内按本条消息开放账户写工具的方向正确，但存在一个可复现的误授权：主人明确撤回签名指令，解析器仍开放修改工具。

| 需求 | 结论与证据 |
| --- | --- |
| 保留普通群消息，区别正文和授权 | 协议和范围测试通过。不支持的入站消息段只留下固定占位符；其负载、引用和其他人的 @ 不提供主人写授权，出站仍拒绝不支持的段。能识别「发条说说庆祝一下」，未指定改账号昵称还是群名片会澄清。 |
| 群内主人改签名、头像、带图说说 | 范围、图片、回执检查通过：工具只暴露本条指定的字段，回执只返状态，不回传旧签名或其他资料。本条图片明确按索引绑定，未指定的多图不写；内置图按启用清单过滤，实际查看后才可提交。已开始的写操作不因结果未知而重发。否定语句的误授权仍阻塞，见下方。 |
| 本群公告、精华、指定成员名片 | 三种请求均与仓库内 NapCat 接口核对。前两种由程序填当前群、限制条数和字段；成员查询仅允许本条结构化 @ 的目标，且回执群、成员须匹配。真实 Runtime 接模拟 OneBot 的记录里，普通群友读到允许内容而未收到隐藏字段。 |

**S1 阻塞反例（隔离目录，不使用账号）：** 用 Node 直接加载实际 TypeScript 的 ownerDecision，以已授权群、主人身份、单个纯文本消息分别调用。输入「把你的签名改成开心，别真的改」「把你的签名改成开心，先别动」「把你的签名改成开心，开玩笑的」，三个结果都包含 set_qq_profile 指令，字段为 signature，值为包括逗号及后半句的全部内容。group-intent.ts 的 operand 把补充说明误当成未引用的签名正文。建议值边界不明确时澄清；确实需要保留完整多分句签名时可使用现有的引号语法。正例「把你的签名改成「今天开心，继续游！」」已在范围测试中通过，保留引号内标点和原值即可，不应一概禁止逗号。
