# Spec：精简界面解释性文案

状态：Done；2026-11-04，独立验收PASS。

## 背景
用户明确指出「主人只能有一个 QQ」等解释不应堆在界面；软件面向使用者，不面向开发者或AI。

## 目标
删除重复复述控件、描述内部实现的说明，必要限制使用用户能直接理解的短句。

## 非目标
不改业务规则、权限、状态、交互或布局；不删除实际故障、操作后果、输入限制和必要操作指引。不进行页面重设计。

## 当前行为
QQ页复述主人数量、好友记忆与直接发送；模型/记忆/日记页含内部模型、处理预算和生效方式说明；抖音功能限制使用协议验证措辞。

## 目标行为
字段、按钮、状态本身能表达的信息不再额外说明。删除QQ两段说明、重复数量的「唯一主人的 QQ 号」占位文字和主动开关旁的「直接发送」重复提示；模型推理强度说明、记忆提取实现/预算段落、日记模型与更新解释删除。抖音限制简化为「暂不支持私信、分享和投稿。」。

## 功能需求
- 保留「主人 QQ」「可私聊的好友」「群聊触发方式」等清楚标签；权限行为不变。
- 保留扫码、组件安装前置条件、联系人失败、主动未开启、未知发送结果、备份停服/覆盖等对操作有用的提示。
- 仅删除无人使用的对应局部CSS；不调整全局间距或组件。

## 边界条件
没有无内容的说明节点或悬空样式；代码条件分支和表单关联保持。

## 技术约束
S0，仅文案/展示节点，使用已有源码结构和beUI，不加依赖。

## 兼容性要求
API、状态、权限、保存、轮询及既有业务全部保持。

## 验收标准
- [x] 指定冗余说明已清理，关键操作提示仍可见。
- [x] diff仅为文案/展示与直接失效样式，独立验收PASS。

## 待确认问题
无。按用户明确要求及既有web-design规范实施。
