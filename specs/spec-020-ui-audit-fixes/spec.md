# Spec：修复原生巡检确认的界面问题

状态：Done，R1后新的独立验收PASS。EXISTING，dev基线4848d4e，开始工作区干净。用户在原生UI巡检列出7项问题后明确“那你修一下”，范围已充分确认。

## 背景
2026-11-04原生macOS巡检确认浮层定位/状态、表单对齐和信息呈现问题。复现与截图在build/ui-audit-20261104/report.md；不是据静态猜测扩大任务。

## 目标
消除已确认的7项问题，保持浅海蓝、beUI、简洁桌面WebUI及现有业务能力。

## 非目标
不换框架/依赖、不重构业务、不修改Runtime通信或模型协议，不调用真实云模型/平台账号，不修旧后台版本或重打发行DMG。

## 当前行为
声音菜单统一末端对齐且无边界避让；运行菜单开启审批时未关闭、其portal盖住抽屉；长短设置页的滚动条改变内容居中位置；B站操作按钮宽度使输入列不同；旧模型用途文案、重复名称及两种连接状态表意不清。

## 目标行为
1. 共享Popover在窗口边缘自动避让，必要时翻转；声音菜单在380px与900px宽下完整可见，缩放/滚动后仍跟随触发器，保留焦点/Escape行为。
2. 运行菜单打开审批时先关闭自身，抽屉无残留菜单遮挡；关闭后可再次正常操作，不靠提升抽屉层级掩盖状态问题。
3. 设置长短页切换和折叠展开时，页签与内容列横向稳定。
4. B站关键词/BV号两行有一致的输入与操作列边界；常规和窄窗口均整齐，不强迫所有无关按钮等宽。
5. 经历、记忆、QQ及同根因直接相关的用户提示改用当前聊天/语音输入/朗读模型名称，不指引已取消的用途。
6. 模型label与model相同时只显示一次，旧配置不同标签时仍保留有效信息。
7. 顶栏清楚表示本地服务状态，聊天断线提示清楚表示聊天连接；保持必要的错误/重连操作，不伪造连接成功。

## 功能需求
定位约束在共享Popover职责层解决，菜单动作的关闭在拥有菜单状态的组合层解决。样式与文案局部修改，不改变业务输入、提交、账号数据和既有持久化。

## 边界条件
380×500和900×680；靠左/右/上/下触发器、浮层打开时缩放；菜单→抽屉与Escape；有/无垂直滚动条；模型标签相同/不同；服务可达但聊天流断开。

## 技术约束
沿用普通源码模块和本地beUI。S2：共享Popover影响多个菜单并涉及浮层交互，其余为局部样式/文案。仅检查相关前端模块与复现路径，不运行全项目套件。测试使用隔离fixture，原生检查不得保存用户配置或停止原有Runtime。

## 兼容性要求
Desktop/Web共享组件都生效；不修改schema/API/密钥/平台启用状态，保留旧模型标签。
