- B站扫码、等待手机确认、过期和登录失败，以及抖音浏览器验证、手机确认、账号不符和读取状态失败，都有相应的列表标签或详情反馈。详情的重试入口会刷新本卡。
- QQ 外部服务的凭据被拒在对应卡片中可见，异步保存回复设置失败在设置控件旁可见。QQ 刷新二维码失败后的自动恢复仍会展示过时的报错。

## Validation

- 风险级别为 S2。独立审阅连接列表、三种详情、状态选择函数、读状态失败提示、相关 Runtime 状态契约和定向浏览器夹具，并目视已有的 QQ 等待扫码截图。
- 实施报告记录了定向浏览器用例通过 1/1、入口类型检查通过。既有用例覆盖用户重试成功，但未模拟上次刷新失败的 `operationError` 在随后成功的状态轮询中仍由 Runtime 返回。此次验收未重复运行上述检查，未操作真实服务或账号。

## Issues

- 点击“刷新二维码”后，托管服务的异步请求可能失败。此时 `apps/runtime/src/channels/managed/service.ts` 的 `launch` 同时记录 `error` 和 `operationError`，并继续轮询。随后轮询成功进入扫码、手机确认或在线阶段时，`poll` 更新 `error`，保留上次操作的 `operationError`。在 `apps/desktop/src/components/QQConnection.tsx` 第 85–89 行，登录阶段会因上次操作是刷新而继续展示旧错误，在线阶段也会直接展示它。因此健康状态已经恢复时，“等待手机确认”或“已连接”仍可与“QQ 组件未能完成操作，请重试。”并列，直到下一次组件操作。

## Regression Risks

修复时须保留当前登录失败，以及账号恢复在线但保存回复设置确实失败的局部反馈。账号在线不能证明设置已保存。

## Required Rework

1. 按操作结果的有效期区分当前连接故障、已被正常登录进度取代的刷新错误和仍有效的设置保存失败。
2. 在连接夹具中保持旧的刷新 `operationError`，覆盖实际失败可见、随后恢复到手机确认或在线时旧红条消失，并保留现有设置保存失败断言。只需重验受影响的连接路径。
