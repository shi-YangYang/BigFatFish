# 登录等待与连接错误提示

## 背景
托管 QQ 等待扫码时，页面把 OneBot 尚未连通的诊断单独显示成红色断线提示，同时显示“正在重连”和“等待扫码”。
## 目标
用户看到当前应执行的登录步骤。真实连接失败显示在对应连接卡或操作旁。
## 非目标
不修改账号、凭据、重试策略、平台协议或通用通知系统。
## 当前行为
QQ 独立渲染传输层与登录组件状态。B站与抖音也分别渲染登录进度、错误和轮询失败，可能产生冲突或页面顶部的重复提示。
## 目标行为
准备、启动、扫码、已扫码待手机确认、打开浏览器和验证等正常步骤显示为进度。当前状态决定主标签；后台重试或上次尝试的错误不覆盖当前正常步骤。真实失败、凭据被拒、无法读取最新状态或二维码过期等在相关卡片内给出适当反馈。
## 功能需求
- 修复截图中有二维码且托管组件在登录、渠道在重连的组合，只展示扫码所需的状态和操作。
- 对 QQ 外部服务、B站和抖音按各自实际状态处理。真实终止错误、明确失败的用户操作仍可辨认；避免重复、跨模式串用或无关的页首告警。
- 检查连接列表与详情中直接相关的状态判断，保持一致。保留连接、刷新、断开和重试入口。
## 边界条件
涵盖二维码尚未生成、手机确认、真正连接失败、账号或凭据错误、后台状态读取失败和从失败重试进入登录。操作记录中的历史失败仍属记录。
## 技术约束
使用现有平台状态和 beUI 组件；保持 Desktop/Web 共用界面，避免改变真实账号或重启服务。
## 兼容性要求
现有配置与 API 兼容。
## 验收标准
- [x] QQ 登录与重连并存时展示扫码，无矛盾重连标签、页首告警或错误 toast。
- [x] B站和抖音正常扫码/确认/验证也无误报，真正故障在关联位置可见。
- [x] 状态切换与现有操作可用，定向回归和独立验收通过。
## 待确认问题
无。
