# Spec 006: P4 B站复用接入

状态：代码验收PASS。新的独立accept_p4已验收，实际本机路径通过；真实B站/QQ账号、云模型和Windows仍未验证。

## 背景

用户确认主要上游为 Alterssss/dsh-bili-whale，并提供 pond/life 作为参考。已核实 whale 是 Node CLI/库与 DSH 插件，不存在可直接调用的独立 MCP/SDK；其默认凭据位置和独立调度不能直接带入本产品。

## 目标

复用现有 B站能力，通过同一 Runtime 插件体系完成账号状态、搜索、视频观看/理解、观看记录、统一兴趣与经历同步，让实际 B站活动出现在同一时间线和日记中。

## 非目标

不重写成熟上游功能，不加载第二套大脑/记忆/调度器，不读取现有 ~/.bili-ai 凭据，不绕过登录、会员内容、验证码和访问限制。写操作未经统一权限/审批不得执行；P4 不以自动点赞、评论或私信作为默认体验。

## 当前行为

只有固定上游源码、版本、许可证与接口研究。没有 B站插件或授权账号实测。主上游 CLI 具有搜索、评论、字幕、watch-video/debrief 等功能，部分命令可能退出码为零却没有完整结果。

## 目标行为

用户安装/启用插件后可查看依赖和登录状态，按明确操作进行登录或导入自己提供的凭据。搜索和观看返回真实内容与能力限制，已完成活动进入统一经历/兴趣/日记；失败、无字幕、无画面、未登录或依赖缺失不会被显示为已观看理解成功。

## 功能需求

1. 复用固定 commit 的 whale CLI/必要库，保留 MIT 许可与第三方来源。只做明确必要的配置/路径适配，不复制整套应用或加载其自动分享、私信监控、独立调度和 DSH 人格逻辑；记录补丁与版本兼容范围。
2. 上游所有凭据、配置、缓存和工作文件明确使用本产品插件数据目录。将硬编码 ~/.bili-ai 等路径通过最小适配改为显式 data-dir，不能通过改 HOME 劫持进程环境，也不能自动导入其他应用凭据。
3. 登录/状态管理复用已核对的 QrAuth 与账号验证接口，只有 isLogin/mid 等真实结果才能成为已登录状态；UI 展示过期、扫码待确认、验证失败与退出状态。账号凭据按统一密钥与文件权限策略保存，不进日志。
4. 搜索、视频详情、评论/字幕等读取，以及实际 watch-video/debrief，通过受控子进程和明确命令白名单调用；参数按 argv 传递，限制输出/文件尺寸、超时和路径，不能让模型注入 shell 或任意上游命令。
5. 字幕/帧/视频结果检查实际文件、结构和完成标记，而不只看退出码。画面依赖 ffmpeg 和可用视觉模型，字幕与图像分别标注证据范围；缺少能力时明确部分结果，不能把元数据读取描述为完整观看或理解。
6. 通过统一模型路由进行必要总结/理解，记录来源 URL/BV、时间、文本/画面证据与结果。DSH 只作为统一引擎；上游独立模型调用不静默使用其他凭据。
7. 观看任务可取消、去重并在失败/重启后显示实际状态；同一活动事件幂等进入 Runtime 的 experiences/activity_records/interests。模型推测的偏好遵循 P2 记忆策略，不自动成为主人事实。统一日记可以检索并引用该活动。
8. 插件 manifest、配置 Schema、权限、依赖、版本、来源、启停/健康/dispose 通过 P3 管理基础实现；禁用停止任务，不在后台继续轮询或写平台。
9. Desktop/CLI 提供真实配置、登录状态、搜索/观看、任务进展与历史查询；文档说明上游许可、固定版本、依赖和用户授权步骤。未来更新必须能判断与本地路径补丁是否兼容。
10. 已观看视频可通过既有QQ权限/审批分享给已授权对象，预览准确视频URL、标题与正文，批准后才由统一发送门执行；QQ不可用时明确显示需配置。P4不加载上游自主分享/站内写计划，不新建绕过现有审批的分享通道。自主浏览由P5统一调度接入本阶段活动能力，不在B站插件再建独立调度器。

## 边界条件

无字幕、字幕接口返回空、仅部分视频可访问、ffmpeg 缺失、过期登录、二维码过期、重定向/恶意路径、超大输出、同视频重复任务、进程异常/取消、源内容与模型结论不同、上游退出成功但文件缺失、禁用时仍有在途任务。

## 技术约束

whale 主来源为 docs/upstreams.md 核实的固定 commit；pond/life 仅在明确需要其独立 Python MCP 能力时复用，并保留其 NOTICE/共同上游来源。不能仅因 Python 进程启动就宣称完整插件可用。所有产品状态和记忆属于 Runtime。

## 兼容性要求

保持单根工程与普通模块；账号数据在安装目录外。未装插件或依赖失败不影响本地聊天/QQ。上游行为变化是可诊断错误，不能吞掉失败。
