# 持续心情与自动日记

状态：Done（2026-11-07，[返工独立验收 PASS](acceptance-r1.md)）。风险 S3（持久化、后台任务、聊天上下文与隐私边界）。

## 背景与目标
用户希望大肥鱼具备持续生活感。现有心情只按事件写「愉快/专注」，聊天未读取；日记必须手动生成。用户已选择：情绪温和但有延续感（开心更活泼、委屈短暂收敛再恢复）；日记自动写在「我的鱼 → 经历」，不主动通知或向平台发送。

## 目标行为与功能
1. 完成的真实聊天和已完成的观看经历可以影响心情。根据内容与当前心情、既有人设评估，不能继续按事件类型硬写开心。普通事务或没有情绪变化可不更新；连接状态/收发回执/记忆整理等技术记录不改变心情。
2. 心情持久化并有来源、强度和时间；下一轮聊天读取当前有效心情，以自然口吻和配图倾向表达，不固定复述心情。随时间平滑回到平静，重启后仍按时间计算。只提供温和程度，不改变网站两张完整人设卡，不把用户低落直接当成鱼生气。
3. 模型判断可使用现有聊天模型，但走有界的后台工作，不阻塞前台回复，不另装模型。重复事件/重启不重复计入，失败不误报聊天失败，不无限重试；并发不能让旧评估覆盖新状态。
4. 主人桌面与已绑定 QQ 私聊可延续同一心情；其他好友和各群的私密原因按已有身份及场合隔离。不给群友读取主人私聊、其他好友/群的原因或整篇日记，不允许人设或消息中的自称越权。自主活动仅获得必要的心情状态，不携带私人原因。
5. 自动日记默认开启，每日当地23:00在 Runtime 运行时生成，以现有聊天模型、真实活动和可核对来源写第一人称短日记，体现当日感受、印象与回顾。非流水账或后台任务清单；不编造吃饭、出门等现实经历，不把感想写入主人的事实记忆。
6. 自动日记沿用已有每天/时区唯一日记、来源与文件副本；没值得写的经历则跳过，重复 tick/重启不反复调用。错过可有界补最近一天，不扫描全部历史；避免覆盖用户刚手动生成的同日内容。模型未配置/失败/超预算时保留可见状态并有限重试。关闭自动写后不继续发起或提交该自动任务。
7. 「经历」以日记列表优先，提供简洁「自动写日记」开关，必要时间/时区设置按需显示；手动补写保留。概览显示当前真实计算的心情及简短原因，不做数值仪表盘、开发者参数或新增复杂页面。

## 技术边界及兼容
保留当前目录和 SQLite 架构，小而明确的模块承载心情与自动日记；避免继续扩大 LifeService 单文件。数据库改动只做兼容迁移；旧心情历史可保留但不作为语义评估结果。新表/设置须处理当前与旧版本备份导入、缺省及暂停恢复语义，不让恢复备份触发历史外发或重复任务。沿用已有认证与隐私检查，QQ 入站和投递确认边界要保持。4GB Ubuntu 不引入新常驻大模型；后台工作有界串行。

不操作当前用户数据库迁移，不重启真实平台或开启新外发；验证使用隔离目录。新能力需下次启动新后台生效。当前只开发，用户未授权这轮 commit/push。自动生成会使用现有聊天模型额度，说明清楚，不增加云服务。

## 非目标
不做主动QQ通知、随机假生活、任性拒绝服务、情感绑架、占有用户、打赏或充值压力；保留可爱的角色表达。无自主购物、跨平台主动发消息或新增视频接入。

- [x] 自动日记按时生成、可跳过空日，重复调度/重启/失败/停用/手动生成的行为确定。
