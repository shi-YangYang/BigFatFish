# Spec 033：QQ 消息页仅保留操作记录

状态：Done；独立验收PASS，见acceptance.md。

## 背景
用户截图指出发送消息与自动回复记录，并明确要求删除，消息页只保留操作记录。dev基线3b922f3、开始干净。

## 目标
精简「连接 → QQ → 消息」为单一操作记录卡片。

## 非目标
不删除历史数据库数据，不改QQ自动回复本身，不移除B站分享、CLI及插件所用的后台发送服务或改变其授权设置。

## 当前行为
QQMessages同时读取渠道状态、投递记录和审计，展示自动回复记录、发送表单、主动发送记录、操作记录；前端包含附件读取及发送反馈逻辑。

## 目标行为
消息页只显示操作记录及其必要的加载/失败/刷新/空态。记录继续自动刷新、内部滚动，离开页签停止轮询。

## 功能需求
- 删除发送消息表单（对象、文字、附件、直接发送）、自动回复记录和主动发送记录。
- QQMessages仅请求审计接口；删除本页面的发送、附件处理、配置/投递读取与状态。
- 删除已无生产调用的投递展示组件/帮助函数/专属样式和无用props，保持中文操作记录映射与共享模型错误处理。
- 文档同步；已有测试中仅移除已删除展示功能的断言/导入，后端失败与取消/权限/未知交付检查保留。

## 边界条件
无记录、读取失败后刷新、在途请求遇到离页、自动轮询迟到响应、长操作记录内部滚动。

## 技术约束
仅现有前端QQ展示及直接关联文档/测试清理；Desktop/Web共用，无Runtime/API/schema/依赖改动。

## 兼容性要求
QQ回复设置、自动回复能力和历史持久化不受影响，现有中文审计事件继续显示。

## 验收标准
- [x] 消息页仅操作记录卡片，三项已删除展示无残留。
- [x] 只获取审计，无页面发送或附件逻辑，轮询卸载/过期响应保护保留。
- [x] 不再使用的前端组件/帮助函数/样式已清理，文档和现有测试引用同步。
- [x] 内部滚动/中文记录/必要错误恢复保留，S1必要检查及独立验收通过。

## 待确认问题
无。依据截图和「消息里面只保留」限定为消息页功能精简。

## 跟进：操作记录只显示需要处理的问题
- 「连接 → QQ → 消息」只显示异常结果，例如回复生成失败、发送失败、部分发送和发送结果待核实。成功、开始发送、正常跳过、主动取消、配置同步和无法识别的旧状态不进入列表。
- 按最新问题在前展示，最多 20 条，新问题自动替换最旧的展示项。同一轮部分发送不再分别堆叠子消息失败。先筛选问题再限条数，正常活动不会挤掉较早的问题。
- 保留卡片内滚动、自动刷新、重试和清晰的空态；原始审计、CLI、消息投递和登录会话不改，不删除用户历史。仅影响 QQ 消息页。
