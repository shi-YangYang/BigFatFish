# Spec 009: P7 Web Console 与插件生态

状态：本地代码及返工独立PASS。三项首轮缺陷经新实施和新的独立accept_p7_rework闭环，安装产物已同步。P6基线a0e8f61，root按授权本地提交P7；Windows/真实账号/正式发行与抖音既有缺项仍单列，不代表完整产品完成。

## 背景

Desktop/CLI 与平台插件的产品行为均归统一 Runtime。需要真正的远程管理入口，以及第三方能够按文档独立开发、安装和维护插件的稳定接口。

## 目标

实现经认证的 Web Console，与 Runtime 的真实配置、聊天、记忆、任务、插件、审批、日志及备份行为联动；完成插件 SDK、独立安装启停更新、可运行示例和开发者文档。

## 非目标

不把静态页面或直接读数据库的网页当控制台，不无认证开放公网管理，不声称普通子进程/RPC天然构成 OS 沙箱。不创建重复公共包/多包workspace，不伪造在线市场或发布下载链接。

## 当前行为

尚无 Web Console 或完整插件生态。P0–P5 已有 Runtime API、三个平台适配、会话/权限/记忆和活动；P6 已实现离线维护核心、桌面原生设置与独立产物，本地代码验收已通过。现有平台加载仍依赖内置资源，前端连接依赖 Tauri。P7 须复用这些实际接口并补齐入口与生命周期，不能另建一套业务后端。

## 目标行为

用户明确启用远程管理并配置可信 TLS/认证后，从浏览器登录同一条鱼，管理真实状态与任务。插件安装前能看见来源、许可、兼容性和权限；授权后独立运行，停止/撤销立即有效，更新失败能回退且不损坏数据。

## 功能需求

1. Console 通过统一 Runtime API/事件完成主要管理：Home/Chat/Life/Memory/Channels/Plugins/Models/Tasks/Permissions/Logs/Settings；可复用前端普通组件和请求逻辑，不能复制数据库访问或平台业务规则。
2. 远程管理默认关闭或仅loopback，开启时有独立认证与部署配置，公网路径必须HTTPS/WSS。登录秘密不经URL/日志传播；会话有过期/撤销，密码或等效凭据安全存储；提供暴力尝试限制、CSRF/Origin/Host校验与WebSocket认证。
3. 不能将本机connection token公开给网页，也不能为了前端方便取消认证/跨站保护；反向代理的可信头和来源边界明确。未配置TLS的远程模式拒绝启动或保持明确不可访问状态，不能默默降级。
4. Web上的模型凭据设置只写入，查询不回传；插件安装、权限变更、审批、恢复和更新均调用同一受保护执行边界。错误、断线/重连、未登录和权限不足准确显示，页面没有假按钮或假成功通知。
5. Plugin SDK 明确 manifest、配置Schema、消息/事件、生命周期、健康、工具注册、权限请求、存储作用域、取消和版本兼容契约，涵盖Channel/Activity/Tool/Model/Memory/Personality/Service/Integration的扩展方式。无需为此创建monorepo公共包；提供可随产品使用的普通模块、类型或协议文档。
6. 插件以独立可安装产物提供，包含ID/版本/作者/许可/Runtime兼容范围/OS/依赖/权限/入口/校验元数据。安装支持真实本地或明确远端来源，验证归档路径、大小、完整性、兼容和冲突；不任意执行安装脚本或静默安装额外权限。
7. 安装界面/CLI先展示具体来源、许可和权限，用户明确授权后启用。默认权限拒绝，权限变化或更新新增权限须重新授权；所有宿主能力通过统一检查，不能通过另一RPC方法绕过。
8. 优先采用独立子进程和受限RPC；限制消息大小、超时、并发和可访问宿主服务，插件崩溃不拖垮Runtime。必须准确说明实际文件/网络隔离程度，未经OS级验证不得称为安全沙箱；同进程插件如确有必要须明确受信任边界。
9. 安装/启用/禁用/停止/健康/dispose/更新/卸载均真实执行并保存状态；退出清理子进程、订阅和队列。更新先验证暂存产物，停止旧实例后替换，失败可回退；默认保留用户数据，卸载/清除数据作用范围明确。
10. 示例插件必须能按文档从独立目录构建或运行、打包、安装、授权、启用、调用、停止及更新，不能依赖源码仓库隐式路径或另一套人格/记忆。至少覆盖实际工具/事件能力与拒绝权限的负例。
11. 插件目录只列真实存在且许可明确的项目/版本/来源；本地目录可作为初始发现入口，不假称在线商店已运行。平台内置插件和第三方示例遵守同一基本管理契约。
12. 提供开发者完整文档：架构与扩展边界、API/事件/SDK、插件manifest与权限、开发/调试/测试、发布产物格式、兼容升级、MCP/辅助服务、模型路由、记忆与审批、部署和故障诊断。文档命令通过实际示例验证。
13. 收口产品Model Router目标：聊天/复杂决策/视觉/记忆/ASR/TTS的路由必须有实际消费者，不能只存配置字段。复用前序视觉/ASR实现，补足可运行的语音识别/合成Service或Model适配、明确兼容协议、输入大小/媒体类型/超时与凭据边界，Desktop/CLI/Web可显式调用并查看/播放真实返回结果。语音处理不替代聊天的DSH主引擎，也不默认向平台发送媒体。使用本地模型或协议夹具的结果与真实云服务验证分开记录。
14. 收口前序已明确保留的QQ媒体适配：将实际视觉/ASR消费者接到授权入站媒体，并完成产品所需的文件/媒体发送路径。使用固定上游真实接口、受限媒体存储及明确账号/目标，上传与发送都经同一权限/审批；不能让外部文件引用变成任意本机路径或未受控URL访问。未支持的类型和外部账号验证继续准确展示，不能把仅保存类型元数据称作完整媒体理解或文件发送。
15. 收口产品 AgentEngine 的工具注册与工具活动要求：当前 P1 桥明确拒绝所有工具，插件仅能手动调用不等于 Agent 可使用。通过 Adapter 的显式工具契约把已授权插件工具接入同一 DSH 回合，真实工具请求交 Runtime 校验、执行并返回结果，界面展示对应活动；取消、超时、插件停用及权限撤销须传到实际执行边界。聊天主体和受众不能因此获得主人管理权，模型只能提出需审批的动作，不能批准自身请求或绕过现有社交审批；保留对任意 shell/文件等未授权能力的拒绝。

## 边界条件

未登录、过期会话、CSRF/恶意Origin/Host、WebSocket无授权、反向代理头伪造、断线重连、恶意归档/路径穿越、相同插件ID冲突、未知权限、更新增权、进程崩溃/卡住、RPC超大/超时、撤销后迟到调用、版本不兼容、更新回退和卸载数据保留。

## 技术约束

Runtime仍是唯一业务核心；沿用现有技术栈和普通模块。远程敏感操作不绕过既有审批或数据安全。适用网页内容规则，面向真实用户展示状态和操作，不展示开发实现说明。新增外部发布/托管服务需要明确授权，不由本阶段自动创建。

## 兼容性要求

本地Desktop/CLI保持可用，Web未启用不影响它们；插件协议版本与兼容策略明确。平台插件使用相同记忆、权限和事件；更新不能破坏此前授权或未完成任务记录。

## 待确认问题

正式公网域名/TLS、托管和发布权限尚未提供；先使用隔离本地TLS测试部署验证实际认证/通信。无需把产品功能发布到外部服务才能实现控制台，但未执行的公网部署不能声称完成。
