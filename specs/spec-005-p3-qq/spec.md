# Spec 005: P3 QQ 个人小号

状态：代码与已执行路径验收PASS。首轮两项阻断由新实施者修复、新独立验收逐项闭环，见Plan/Acceptance。真实QQ/Windows/云与完整媒体缺口仍单列，不标完整阶段全部完成。

## 背景

用户指定 NapCat/OneBot 接入个人 QQ 小号，所有平台共用同一人格和记忆。已检查 NapCat、QQ Relay 与 QQ Bot 的源码、协议和许可，证据见 docs/upstreams.md。

## 目标

用户在外部 NapCat 完成账号登录后，可配置 QQ 插件接入 Runtime，实现受授权的私聊/群聊、主人识别、统一聊天与记忆、消息去重、断线重连、健康状态及操作审计。

## 非目标

不绕过 QQ 登录、验证码或风控，不读取其他应用账号数据，不捆绑或复制 NapCat 受限制许可代码，不加载上游各自的 DSH 大脑。不把协议模拟测试当成真实 QQ 收发验证。

## 当前行为

尚未实现 QQ Adapter 或实际账号连接。上游协议已核实；NapCat 的连接成功、get_status.online 和真实账号登录是不同状态。

## 目标行为

用户看到未配置、连接中、未登录、在线、重连和错误等真实状态；设置主人及允许群后，指定账号的消息通过统一 Agent 回复。停止插件或撤销授权立即阻止新消息处理和发送；重启后连接配置及去重状态保留。

## 功能需求

1. 通过普通源码模块实现 OneBot 11 Adapter 和 QQ 插件生命周期。至少支持 NapCat 正向 WebSocket 的实际事件与 action/params/echo 协议；支持范围在 UI/文档明确，不将未实现的传输方式标为可用。
2. 连接使用用户明确配置的地址和凭据，token 进入统一加密存储。校验来源、响应 echo、status/retcode 与字段；拒绝未知或不合规事件，账号 ID 用字符串避免精度损失。远端连接遵守加密传输和明确配置边界。
3. 通过真实 get_login_info 与 get_status 校验账号、自身 ID 和在线状态；get_version_info 用于诊断，不调用错误的 get_version。连接、已登录、请求已接受、消息已发送分别表达，不能因 HTTP 200 或异步 retcode 就认定交付成功。
4. 主人 ID 必须由本机已认证设置明确配置，不能由收到的聊天消息声明。默认仅允许主人私聊；群聊需要显式允许群与触发规则（如提及机器人），拒绝自身消息、未授权用户和任意群触发。
5. 通过统一会话/人格/模型/记忆处理消息；会话映射按账号、私聊或群上下文隔离，避免跨用户/群混入聊天历史。群内他人陈述不能自动成为主人事实，长期记忆遵守 P2 确认策略。
   同一Memory Engine须按实际发送对象控制可见范围：本机/主人私聊可使用主人记忆，群聊与其他人的会话默认不注入主人私密记忆，只有用户明确允许共享的内容才可跨该边界。共享引擎和人格不等于向所有联系人公开全部记忆；权限检查在检索/发送边界落实，不只写在提示词里。
6. 用户授权后的普通聊天回复可自动发送；主动私信、群广播、删除和账号变更等高风险行为不从模型直接执行。建立权限声明、授权撤销、审批及审计边界，所有发送入口经同一检查，不暴露任意 OneBot action 透传给模型。
7. 事件以账号/消息 ID 等真实标识持久去重，处理与发送有可查询状态；未知发送结果不能盲目重试导致重复消息。断线采用有界退避，保持配置并区分网络问题、凭据拒绝和登录失效。
8. 有文本/消息段解析、长度限制、群提及与引用回复。按产品目标保留图片、文件、语音消息的实际类型与安全元数据，入站/出站适配不能只把全部消息当纯文本；媒体理解尚无消费者时明确说明不能理解，不编造转写或图片描述。附件获取/发送只接受明确支持且经校验的引用，不任意抓取不可信URL或读取本机路径。视觉/ASR消费者在P5/P7继续接入，未实现的媒体行为明确列出，不删除产品要求。异常payload、非消息事件不进入模型。配置变更和禁用时处理在途任务与重连计时器。
9. 插件具备 manifest、版本、来源/许可证、操作系统、配置 Schema、权限、initialize/start/stop/health/dispose，Runtime 集中管理状态。P7 完善通用独立安装/更新，P3 的基础接口应能自然复用，不能建立第二套插件治理。
10. Desktop Channels/Permissions 和 CLI 真实管理配置、连接、主人/群授权、启停、审批与状态；错误、未登录、依赖缺失和需要用户扫码的状态准确展示。日志及审计不包含 token、完整私人消息或模型凭据。
11. 主动消息由本机认证入口创建待审批项，展示准确接收对象与内容；批准绑定该操作及参数、有效期和一次执行语义，拒绝/过期/撤权不执行。普通已授权入站回复与主动消息明确区分。当前未提供的删除/账号修改能力保持关闭，不以任意action透传替代。

## 边界条件

token 错误、账号 ID 不匹配、未登录、消息重复与乱序、自身消息、同群并发、上下线抖动、发送超时后迟到响应、Runtime 重启、授权撤销期间生成、停止插件后重连、超长或畸形消息、群名/昵称冒充主人、外部平台速率限制。

## 技术约束

NapCat 作为用户另行运行的外部程序；不捆绑其代码。QQ Adapter 通过标准协议实现，参考代码只有许可证确认后才可复用。Runtime 统一模型、人格、记忆、任务、权限和审计；插件与 UI 不直接读写业务数据库。

## 兼容性要求

继续单根 npm 与普通源码模块，不引入独立包。保留 P1/P2 既有会话与记忆行为；QQ 未配置或离线不能影响本地聊天。实际账号/系统支持以执行证据为准。
