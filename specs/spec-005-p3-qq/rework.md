# P3 首轮返工

范围：首轮Acceptance两项确定问题及同根因直接路径，不开始P4，不更改目录/依赖或放宽正确断言。

1. 共享撤销的最终发送边界：将此次模型生成实际使用的记忆可见范围/快照与回复绑定，不能在生成后重新取得新快照来授权旧内容。账号健康等异步检查完成后，在真正调用send_*前同步复核该回复仍可发送；范围变化时阻止外发并准确记录为未发送/撤权，不能误报sent。避免各调用点复制记忆权限规则，修复应在ChatService提供的生成授权信息与统一发送检查之间保持明确接口。普通主人回复及用户明确批准的独立主动消息保持各自授权语义。
2. 不合法token与初始化隔离：保存前依据实际HTTP Header/Bearer能力验证，失败不改变旧配置/密钥/revision/运行状态；已有旧异常渠道配置仍应允许Runtime与本地API启动，渠道显示可查询、可修正错误。检查连接初始化路径的同步异常并在正确渠道边界隔离，不能只吞报错假称online。不破坏缺少master.key时的安全拒绝、不静默生成新密钥，不吞核心DB/数据错误。

Risk Level S3（隐私/凭据与核心可用性），但验证定向：已完成模型→挂起发送前get_login_info→撤销共享→放行，必须没有send_*；保留正常未撤销发送对照。非法header token API拒绝且旧状态不变；旧库合法加密但不可用于header的QQ配置重启后Runtime/本地聊天可用并可修正。检查媒体/普通审批与撤权发送的直接回归，保留既有master.key缺失用例。

使用隔离临时DB/WS夹具，真实DSH仅在相关引擎接口变化确有必要时验证，不重复整个P0/P1/P2/原生矩阵。按修改执行最小类型/Lint/构建资源检查，记录实际范围与结果。新实施者不做最终验收、不操作Git；随后新的独立验收者复验。
