# Spec 036：刷新 QQ 好友与群聊

状态：Done；独立复验 PASS，见 acceptance-r1.md。

## 背景
用户新增 QQ 好友或加入群后，Desktop 列表不会更新，要求增加刷新 icon。dev 基线 ccb4623；已有未提交交接记录为用户撤销自动 commit 授权，必须保留。

## 目标
无需重启/重新登录 QQ，在回复设置点击一次刷新图标即可从当前账号重新获取好友和群聊。

## 非目标
不自动授权新好友/群，不保存回复设置，不变更主人、账号、登录态、插件或外部服务模式；不增加全平台自动同步机制，不重启真实开发会话，不提交。

## 当前行为
ManagedQQ.poll 只在 configuredAccount 变化时读取联系人；GET contacts 仅返回内存缓存。页面每 2.5 秒轮询不能刷新真实联系人。

## 目标行为
托管 QQ 在线时，回复设置标题栏有一个与既有 beUI 一致的刷新图标按钮，tooltip/aria-label 为「刷新好友和群聊」。点击直接读当前账号，成功后更新主人选择、好友列表和群列表；保留所有已选范围、手填值和未保存草稿，新增项默认不选中。

## 功能需求
- Runtime 增加受既有管理认证保护的联系人刷新入口，主动调用 get_friend_list/get_group_list；复用登录时列表读取职责，不用重连或重新应用配置来刷新。
- 请求期间防重复提交；刷新成功替换列表，失败保留同账号旧列表并通过已有临时提示给出中文失败反馈，可重试。
- 停止、账号切换、组件新 generation 或较新刷新发生后，迟到响应不得覆盖当前列表；异账号缓存不得显示为当前账号的联系人。校验实际 OneBot 账号与登录状态。
- 页面轮询的旧缓存响应不得覆盖刚刷新的结果；刷新不可误提交表单或清除编辑状态。
- Desktop/Web 共用按钮行为；新接口的原生请求超时须覆盖实际有界网络读取时间，不遗留默认 5 秒超时。

## 边界条件
空列表、新增/移除联系人、网络失败、快速重复点击、刷新中停用/切换账号、页面离开、未保存的好友/群/主人草稿。

## 技术约束
使用当前普通模块和 beUI 按钮、既有图标或已安装 lucide-react，不加依赖/schema。后端只读取联系人，不发送消息或自动改变授权。

## 兼容性要求
现有 contacts 缓存查询及扫码流程保持；独立 NapCat 仍按原界面手填，不为本次新增外部服务联系人发现。

## 验收标准
- [x] 在线托管回复设置可见刷新 icon，尺寸/对齐/无障碍与现有控件一致。
- [x] 点击后获取真正最新的好友、群列表，缓存、页面三处选择同步更新。
- [x] 未保存设置和既有选择保持，新成员不自动选中。
- [x] 请求中禁重、失败保留旧列表并提示、迟到结果和账号边界正确。
- [x] 相关子系统检查及独立验收通过；不重启真实实例，不 commit。

证据来自相关集成回归与实际组件的隔离 UI 检查；真实 QQ 新增联系人联动、Windows 原生窗口未实测。当前旧实例需下次正常重新运行 desktop:dev 加载接口。

## 待确认问题
无，用户意图清晰；刷新对象是联系人列表，不是保存授权配置。
