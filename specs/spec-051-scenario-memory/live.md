# 真实模型测试

通过生产 Runtime 的 HTTP 聊天入口，调用大肥鱼已配置的阿里云百炼 `deepseek-v4.1-flash`。测试使用新建的本机数据库和合成对话，未启用可选的向量索引。原数据目录仅用于读取所选聊天模型的配置。测试没有读取用户原有的聊天、联系人或向 QQ 发消息。

## 测试过程

在对话 A 告诉大肥鱼「我已经订好了海岛露营的白沙湾营地。」另开对话 B 依次说「我给这次海岛露营订好了双人帐篷。」「我下周六要去海岛露营旅行。」「我的旅行改到周日了。我喜欢茉莉花茶。」每轮等待真实回复和后台任务结束，读取原话、确认事实、人物字段和场景管理接口。随后停止 Runtime 并结束该进程，从另一个进程启动同一测试库，在新的空对话 C 问「上次说的海岛露营准备到哪一步了？帮我想想具体安排。」

只检查 Runtime 向配置的提供商发送的真实 HTTPS 请求中是否包含场景段落与相应证据，不替换模型回答。命中 L1 或在同一会话答对均不足以证明 L2 正常。

## 首次发现

五项任务全部完成且未重试，但确认事实只有白沙湾营地、仍为周六的旅行，以及茶偏好。场景接口返回空数组，模型请求中没有场景段落。大肥鱼回复「我记得你订好了白沙湾营地，周六那趟，别的我这儿就没记了。」测试由此发现已订物资、具名行程改期及跨回合场景聚合的缺漏。

## 修复后重测

从空库发出完全相同的五条输入。写入和重启后读取运行在不同的 Node 进程、不同 Runtime 实例。新会话的阿里云回复将「白沙湾营地」「双人帐篷」「时间你改到周日了」列为已经定好的事项，另行列出了尚未获知的出发时间和交通方式。

| 核对处 | 观察结果 |
| --- | --- |
| L0 原话 | 对话 A 和 B 的四条原始陈述均保留。新会话 C 只有本轮提问及其回复。 |
| L1 原子事实 | 确认了营地、双人帐篷、旅行和茶偏好四项。旅行记录的当前内容为改到周日，仍保留说周六及改期的两条引文。 |
| L2 场景 | 重启前后 `POST /v1/memory-scenes/search` 返回同一个「海岛露营」。摘要含白沙湾、双人帐篷和改到周日；成员为三个不同主题的 L1。四条引文均可在对应发言人的原消息中找到。 |
| L3 人物资料 | `POST /v1/memory-profile/search` 返回本人喜欢茉莉花茶，来源日期为 2026-11-07。该喜好独立于露营场景。 |
| 模型输入 | 从实际发往百炼的 HTTPS 请求正文中读取到 `<memory_scenarios>`，其中的摘要与管理接口一致。模型实际收到了持久 L2，并能与本轮问题结合。 |
| 队列及隔离 | 五个后台任务均为 `done`、重试次数为零。两次实测的临时数据库、模型凭据和临时会话均已随测试目录清理。 |

本次验证能确认场景实际参与召回；同一回复也允许模型使用已授权的 L1，因此不能仅从回答推断它只使用了场景摘要。

上述实测时，管理接口与上游 system 段的场景摘要原文一致：

> 地点：我已经订好了海岛露营的白沙湾营地。准备：我给这次海岛露营订好了双人帐篷。变更：（2026-11-07的留言）我的旅行改到周日了。
