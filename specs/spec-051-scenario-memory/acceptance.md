# 四层记忆独立验收

**通过。** 涉及 SQLite 升级、归档和跨群披露，按 S3 验证。首轮发现的三处聊天入口问题已修复。

## 已核对

- 真实百炼测试通过 Runtime HTTP 和 DSH，在独立库写入跨会话事实。重启后的空会话把同一持久场景发给云端，答出了营地、帐篷和改至周日的行程。四条原话、三个 L1 成员和独立的 L3 茶偏好均有记录。复核使用已有实测，不重复请求云端。[测试记录](live.md)
- 核对 schema 11 → 12 的事务迁移、场景重建及逻辑归档路径。取场景时按每一个事实验证受众与来源，群内发送前复核成员版本。上下文简称的依据必须出现在同一可见场景，修改或删除原依据会移除该关联。
- 核对浏览器测试从人物资料或场景查看 L1、打开原话的路径，以及模拟 OneBot 在投递前删除仅由 L2 引用的事实后阻止发送的用例。本阶段沿用已有本地 embedding，无新增依赖。

## 首轮需要修正

1. 聊天入口已得到语义命中的事实 ID，却未传给场景检索。底层能根据事实 ID 找回主题，实际聊天只能使用词面。
2. 场景摘要和当前发言人的事实分别按 800、120 字符截断；否定或更正在边界之后时，会把残句交给模型。应传递完整陈述或整条省略。
3. 单一发言人的群场景丢失归属。使用内存库分别以主人身份写入“我的海岛露营集合在码头”“我给海岛露营买好了帐篷”，由另一群友检索。存储记录正确保留主人身份，但模型得到的只有“群内场景”、空的当前发言人事实和第一人称原句，无法识别这是谁的安排。

## 复验

重新核对聊天入口和对应定向集成用例。当前受众筛选后的语义命中已传给 L2。模型得到完整摘要，当前发言人的证据只选完整陈述。单人群场景带有原发言人标识，多人场景保留摘要中每位发言人的标记。

两项定向集成测试通过。模拟 OneBot 的群友输入无词面重叠的改述，由注入的语义命中找到场景，核对了引擎实际收到的主人标识、六条总长超过 800 字符的完整证据及更正句末尾。语义命中在该用例使用测试替身；前述百炼实测使用词面召回。
