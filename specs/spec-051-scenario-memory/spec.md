# 四层长期记忆

大肥鱼采用原始对话、原子事实、场景记忆、核心画像四层。参考腾讯云长期记忆的分工和溯源方式，以本机 SQLite 和已有聊天模型实现。[腾讯官方设计](https://cloud.tencent.com/document/product/1813/132100)

| 层 | 在大肥鱼里做什么 |
| --- | --- |
| L0 原始对话 | 保留发言人、时间和完整原话，供上层追溯。 |
| L1 重要记忆 | 把可独立更正的事实、偏好、安排与确切来源关联起来。 |
| L2 场景记忆 | 把同一可见范围里关于同一件事的多条事实整理为持久的场景，记录当前进展和组成它的证据。不同会话可以接续。 |
| L3 人物资料 | 直接采用明确的稳定自述，并能为与场景有关的资料提供可见的场景依据。年龄和性别等独立声明不需要等待场景形成。 |

## 验收条件

- 多轮谈同一活动的地点、准备事项和改期后，能找到一个包含多个已核实细节的场景。无关话题另存。Runtime 重启后的新会话会用持久场景接续进展。
- L2 可以从「我的鱼 → 记忆」打开，用户能沿事实查看原话。更正、忽略、删除、合并或改变共享范围后，下一次查看和回复使用当前可见事实。用户对个人资料的控制继续生效。
- 群、好友、主人私聊的场景按真实身份和来源组织，单条事实的授权不会连带公开其他私聊事实。同一群的不同发言人可以为同一个场景提供事实，保留各自的归属。混合多个发言人的群场景不得带入主人的私人画像。公共回复复核实际使用的来源。确定长期结论需要可核实的个人证据。
- 升级和归档恢复能使用已有确认事实，分析不阻塞正常回复，沿用本地 small INT8。验证包含真实配置的云端模型、独立临时库和新会话，不向真实联系人外发。
