## Spec Coverage

- `Channels` 静态创建 `QQClient`，客户端与 `OneBotTransport` 位于 Runtime 的 `channels/onebot/`，职责分别为平台动作与传输/健康/重连。旧动态装载器、源码插件及 QQ 平台 reload/suspend/assertPlugin 接线已移除，没有安装目录回退。
- 对照原 `plugins/qq/index.mjs`，发送前账号核验、最终 I/O 守卫、回执与未知结果、媒体字节、连接世代与取消语义保持。现有互动/自主工具仅变更客户端类型和命名；主人/群范围及自主内容边界没有放宽。
- `migrateQQOwnership` 在读取连接配置前以事务一次性转移旧停用/卸载/撤权或损坏元数据的停用意图，只更新 QQ 配置 enabled 和 revision，保留密文和其它配置。settings 标记使用户之后的连接操作不会被旧 SDK 状态反复覆盖；旧行与文件保留但不执行。
- `Plugins` 在解析前排除 `sdk:qq`，因此不枚举、不初始化该旧状态。保留 ID 在 inspect/install/update 及管理调用处被拒绝，未把拒绝放入旧归档共用的 manifest 校验；普通扩展的授权、撤权及 `channel.send` 路径保留。扩展页面使用该 API 列表，没有独立写死的 QQ 卡片。
- Runtime 开始停止后立即触发 `channels.close()`，同步设置 closing、取消生成/自主/媒体并终止连接；Promise 当场捕获错误，随后等待排空并汇总错误。其它扩展关闭滞留不再延迟 QQ 撤权，已执行中的外部写仍沿原未知结果规则处理。
- 构建脚本仅生成 B站/抖音插件包；资源准备显式清理旧 QQ 包、复制目录与 loader 产物。静态 TS 客户端随 Runtime 编译，B站/抖音挂载和资源保留。清理路径只在构建输出内，不处理真实用户插件目录。
- 当前 QQ、开发、安装、架构、上游说明及技术栈与新路径一致，不再要求单独更新 QQ 插件。NapCat 托管实现及版本未修改，属于自有适配代码迁移。备份恢复继续清除插件授权、停用平台连接与自主外发；历史表和用户数据未作纯更名迁移。
