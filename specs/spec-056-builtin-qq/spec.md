# QQ 内置能力

状态：Done。风险 S3（运行生命周期、权限边界、旧状态兼容及构建）。基线 dev / 6fd50d2；[独立验收 PASS](acceptance.md)，无待返工。内置化改动未提交，未应用到真实用户实例。

## 背景与目标
用户要求先本地提交已验收的 Spec055，然后把 QQ、B站、抖音逐步从插件变成固有能力，这轮先做 QQ，允许复用并修改代码。Spec055 已提交 6fd50d2，未推送。QQ 的业务和协议适配代码已由项目自有实现；本轮将其直接纳入 Runtime，消除安装、授权启用或更新 QQ 插件的流程。

## 当前行为
Channels 动态加载 plugins/qq/index.mjs，Runtime 经 Plugins 管理 sdk:qq 的安装目录、权限、停用和加载。发布脚本同时复制源码并生成 qq.bff-plugin。旧安装不会随应用升级而更新，导致业务与插件版本分离。QQ 连接配置位于 plugin_config 的 qq 行，与 sdk:qq 的安装状态不同。

## 目标行为
1. QQ 协议客户端进入 apps/runtime/src/channels/ 下的普通模块，静态导入、跟随 Runtime 编译和发布。保留消息/图片/表情/自主活动等现有行为。按职责组织连接传输和平台动作，不创建新包，不留动态插件目录回退。
2. Runtime 直接创建、启动、停止 QQ 客户端；Plugins 不再安装、列出、启用、停用、更新或加载 QQ。设置的扩展列表不再出现 QQ，用户只在连接页管理它。移除 QQ 专属插件装载和 assertPlugin 依赖。
3. 旧 sdk:qq 状态和磁盘代码不执行、不作为内置能力的权限依据。保留旧文件以免破坏回退，不擅自清除用户文件。旧插件曾停用、卸载或撤权时，迁移须继续保持 QQ 停用；已正常启用的连接沿用既有配置。兼容处理幂等，不让旧插件状态在后续启动覆盖用户新的连接操作。保留账号、主人/好友/群、密钥、表情、记忆、自主开关和操作账本；不重放未知外发。只在隔离数据验证，不运行用户实例迁移。
4. 拒绝通过插件 API 用保留标识 qq 安装或重新加载代码，旧启用/卸载等调用不能影响内置 QQ。第三方扩展仍可通过既有 channel.send 授权向获准目标发送，撤权与取消守卫保留；不扩大目标或写操作权限。B站、抖音及其它扩展继续现有实现。
5. 构建不再生成或携带 qq.bff-plugin、dist/plugins/qq；增量构建也清理这些旧的生成产物（仅构建输出，不删除用户插件目录）。源码与构建后的 CLI/Runtime 都能使用 QQ，无须独立插件包。
6. 保留目前原版 NapCat 的托管/外部服务方案及平台隔离。此次不下载并改造 NapCat 源码，不换协议端。上游固定 4.18.42 LICENSE/README 明确限制基于其代码修改开发及修改版公开发布；内置自有适配器即可实现用户目标，继续遵循用户此前采用原版独立组件的决定。
7. 现有备份范围、恢复后暂停及旧数据可用性保持；没有仅为了更名而迁移数据库表。当前指南、源码导航、技术栈和上游说明同步，不再要求更新 QQ 插件。历史 Spec 和验收保留原事实。

## 非目标
本轮不迁移 B站/抖音，不删除整个第三方扩展系统，不新增 QQ 社交功能，不修改 NapCat、不更换其运行形态，不进行真实账号外发、模型收费调用或自动提交。
