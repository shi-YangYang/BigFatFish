# QQ 回复耗时与连接加载反馈

状态：Done（代码独立复验 PASS；用户已授权启用新版后台，QQ 已扫码在线）。基线 dev / 6d6652c。风险 S3（模型工具循环、发送与取消边界、旧后台兼容），UI 局部反馈按 S1/S2 验证。

## 用户要求与证据
用户报告自主活动和操作记录卡报错、QQ 回复比以前慢，并要求连接中的耗时状态有 loading。随后明确不是无法发送，而是回复过慢，怀疑上下文或工具参数过多。保留原修复范围，不将故障重新解释为完全无法发送。

2026-11-08 根协调只读检查当前实例：Runtime 仍为 11-07 16:31 启动，QQ online、enabled/replyEnabled=true，状态含旧 manifest 无 builtin；self-options/action-issues 两接口返回404，源码已有接口。原生 IPC 允许这些路由，不是前端白名单问题。界面已热更新而后台未重启。不得伪报为账号离线或数据丢失。

只读会话元数据（不输出聊天正文/凭据）显示近期纯文字回合多为11–12秒，约5–7秒调用send_message后还等待第二次模型收尾；实际平台发送约0.2–0.4秒。一次配图回合28.3秒、4轮模型调用，search_stickers两次不同回合均10秒超时；上下文用量约8千–1万token且大部分命中cache。已运行后台尚未包含Spec055新增自身资料/说说工具，不能把本次既有慢直接归因于它们。具体模型供应商真实性/持续性能不由单组样本推断。

## 目标
1. 修复两卡的旧后台缺接口反馈，并能正确重试/恢复：不将404一律吞掉为通用失败；明确需要重启时给简短可行动提示。操作记录两个来源允许独立成功，不因新增动作接口不可用而丢掉原消息问题列表。不用成功空状态掩盖真实失败。
2. 根据实际工具循环减少纯文字回复无意义的模型收尾往返。优先采用已安装固定DSH的正确完成机制，或准确的普通文字输出路径；不得将工具已排队等同实际外发、取消一律当成功、提前跨越权限复核或因省一轮丢掉同批图片/拍一拍。先研究原生工具/turn完成接口，再选择最小可维护实现并报告。保留网站完整人设、自然配图、主人/群隐私、图片实际查看、未知发送不重试。
3. 网络表情短时失败不得每轮重新等待完整10秒。提供有界失败退避/缓存/快速本地回退，保留搜索能力与后续恢复；用户取消不应污染全局失败缓存。不开放新任意网络来源，原SSRF与图片验证不变。不要以永久关掉网络表情解决等待。
4. 按真实身份/当前回合可用能力精简明显无用工具参数或重复上下文，只有证据支持才修改；不凭token总量直接重写记忆或删除能力。任何工具路由的额外LLM调用都须解释是否反增延迟。
5. QQ、B站、抖音连接的初次读取、正在连接/安装/扫码确认/验证/停止、手动刷新和保存等真实耗时状态应有一致loading（beUI现有Loader/按钮busy），反馈就近且防重复提交。等待用户扫码不是错误，不用全页蒙层遮住二维码或让背景轮询持续闪动；已有数据刷新时保持可见。失败/结束/取消后loading必结束。

## 非目标和授权
不修改人设卡风格、不删除功能、不重构记忆系统、不迁移B站抖音架构、不改模型/推理配置、不commit/push。本轮先用本地模型/OneBot/浏览器夹具；不主动云模型调用或真实QQ外发，不修改真实用户聊天和记忆。根协调持有实际实例诊断与最终启用，实施Agent只使用隔离数据；若实际启用需要迁移，完成具体可审结果后按既有规范处理。
