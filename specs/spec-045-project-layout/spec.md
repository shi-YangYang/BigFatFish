# 项目目录职责整理

## 背景
仓库根目录有九份 Markdown，桌面前端的 components 同时放置业务页面、网络相关代码和通用组件，CLI 命令处理与进程、输入也在同一层。
## 目标
根目录 Markdown 只留 README.md，按工作内容能直接找到页面、封装组件、API 与命令。
## 非目标
不创建独立公共包，不修改产品交互、协议、存储和部署位置。
## 当前行为
Web 复用 Desktop 源码，脚手架、测试、资料和许可证脚本引用现有路径。Runtime、插件和辅助服务已经按职责分开。
## 目标行为
README 指向有效的项目和开发入口。源码保留各应用入口，界面、API 与命令按实际职责归档。
## 功能需求
合并重复的文档，保留产品基线、协作约束和仍有用的安全、参与及操作资料。更新受影响的使用者和维护指南。
## 边界条件
兼顾 Web、桌面宿主、CLI 已编译文件路径、测试夹具、样式扫描与 beUI 的许可证；历史文档中对当时快照的叙述可保留。
## 技术约束
保留单根 package.json 与 lockfile，以普通源码模块实现复用。使用原有构建系统和命令。
## 兼容性要求
HTTP、CLI、聊天、登录和连接行为与工程入口继续工作。项目根不放其他 Markdown 的副本或软链接。
## 验收标准
- [x] 根目录仅 README.md，当前资料和规则可通过有效链接抵达。
- [x] 通用组件、页面、API 和 CLI 命令均有明确归属，Web 与 Desktop 共用实现。
- [x] 相关入口构建、定向检查和独立验收通过。
## 待确认问题
无。

## 目录整理后的文档复核
用户指出搬迁后的资料仍有过时内容。对照当前工作区源码、已有验收与用户实际反馈，修正仍在使用的指南、入口和架构说明；原始设计、历史上游核查和阶段验收按其原始时间解读。指南应区分桌面操作与 CLI、实际确认与模拟验证。此次仅改 Markdown，保留目录整理成果，无提交授权。
