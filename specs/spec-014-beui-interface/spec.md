# Spec：全面迁移适用的 beUI 组件

## 背景
用户在Spec013按钮接入后明确要求“能用beui的全部替换”。本轮Done，独立验收PASS：将实际有对应的现有界面组件迁移到beUI，不再限于Button。

## 目标
Desktop/Web的表单、导航交互、浮层、状态展示和聊天呈现采用可追溯的beUI源码组件；保留已认可的DS蓝、72px窄导航、60px单顶栏、居中阅读列和业务行为。

## 非目标
不更改Runtime/API/鉴权/数据模型，不新添平台能力，不重组业务目录/分包，不引入付费Pro组件，不为了“全替换”加入不存在的装饰、上传协议或新交互业务。

## 当前行为
Button已为beUI，Controls仍使用原生Input/Select/Checkbox；UI.Tabs、Drawer和页面details/summary、状态提示/卡片、聊天composer/messages仍自行呈现。Input使用原生change事件，Select/Checkbox消费者也读取event.target；替换时须处理接口差异，不能伪造事件。

## 目标行为
| 现有界面 | beUI落地组件 |
| --- | --- |
| 文本/数字/密码/URL/日期等单行输入 | Input，保留原生属性/ref/验证与值更新 |
| 下拉选择、复选项 | Select、Checkbox；显式string/boolean回调，保留空值/禁用/选项与业务值转换 |
| 页内页签 | Tabs（pill），含中文标签的唯一id和键盘导航 |
| 历史/导航/审批抽屉 | Drawer，关闭/Escape/焦点恢复/背景滚动管理正确 |
| 状态菜单、声音菜单 | Popover及触发器/内容 |
| 高级项、记录、来源等展开区域 | Collapsible，保持默认折叠/展开及内容状态 |
| 图标辅助说明 | Tooltip；不得替代可访问名称 |
| 持久错误/断连/重要提示 | Alert；风险提示与审批错误不能变成自动消失Toast |
| 已有状态标签/等待与计数展示 | AnimatedBadge；状态文字仍明确 |
| 原卡片式业务区域 | Card，保持必要语义，不把全部段落/列表机械装成卡片 |
| 加载反馈 | Loader与已有必要文字 |
| 聊天消息、消息内容/头像槽 | Message/MessageBubble等展示原语，保留原消息模型和角色/错误/停止/朗读入口 |
| 聊天输入区 | PromptInput，受控接入原草稿/模型/上传音频/声音/发送行为 |
| 主导航/历史列表 | 使用适合的beUI Sidebar或可组合导航部件；保留72px导航与按需历史，不强行接入带资源管理业务的AISidebar |

## 功能需求
- 逐类记录实际来源组件、调用点、必要适配和剩余原生项，不能只安装源码不实际使用，也不能假称无对应项已迁移。
- 保持Chat持续挂载、草稿/请求id归属、发送期间编辑、未知结果恢复、外部会话只读、审批局部错误；不让库默认Enter发送或自动清空值改变既有行为。PromptInput需适配Enter换行、发送busy/断连禁止提交但可编辑、只读/无模型禁用输入，继续由Chat负责业务。
- 受控Input必须保留真实原生事件或迁移到明确value回调；Select/Checkbox用实际值回调，不构造假的SyntheticEvent。不以any/类型断言掩盖契约。
- Label关联、required/min/max/type、ref、disabled、submit与表单验证保持。检查中文Tabs id唯一，空字符串选择可用，Checkbox文本点击与空格切换正确。
- Drawer/Popover/Select叠层不能被裁切或被父焦点约束阻挡；Escape按正确层关闭，关闭后焦点回触发器，隐藏Chat不能残留浮层。遵守reduced-motion。
- 控件以40px动作/输入、8px圆角和DS蓝主题为基础，Checkbox等按其语义一致；保留顶部文字100px最小宽度、图标40px。旧CSS不得继续覆盖库基础样式，避免通过追加大量冲突补丁工作。

## 边界条件
窄屏380×500、长中文/路径、多项选择、空值/无数据、禁用/忙碌/无模型/断连、错误/只读、折叠中的受控内容、浮层里的选择器、页面往返、中文输入法组合输入。

## 技术约束
沿用固定官方revision6f153a06d2225ba07a0137f317ce19faf8da69ef和源码分发/MIT模式；从官方组件依赖闭包引入必要源码与lucide等确需依赖，锁定版本，不升级无关依赖。根单manifest，源码普通模块，保持两Vite构建与随包许可证。

## 兼容性要求
库没有独立通用Textarea：人格/JSON/长文本编辑保留原生textarea并统一主题；隐藏file input和浏览器audio、品牌FishAvatar img、语义HTML/布局容器也可保留。它们是明确边界，不是遗漏迁移；不将通用文本域硬套带提交逻辑的PromptInput。Checkbox仍保留复选语义，不为凑Switch组件把所有布尔项改成即时生效开关。数据无需迁移。

## 验收标准
- [x] 上表适用组件真实通过beUI实现，覆盖清单和明确原生边界完整，无仅导入未使用或未记录遗漏。
- [x] 全部现有前端页面仍可访问，原事件/值转换/提交/权限提示保持，新增控件交互与上述边界检查通过。
- [x] 聊天/历史/导航/审批/模型/通用/数据/人格/记忆/平台/扩展/声音及Web登录代表视图保持排版；1100/820/640和380核心视图无横溢出、发送可见。
- [x] 中文Tab的id/aria引用唯一正确，输入/选择/勾选的label和键盘语义有效，浮层焦点与reduced-motion正确。
- [x] 两前端构建、相关类型/lint、原定向交互回归与覆盖迁移风险的必要检查通过，新独立验收实际看图与源码。
