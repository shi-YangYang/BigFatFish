# Spec：统一桌面图标

状态：Done（独立验收 PASS）；2026-11-04。

## 背景
用户认可当前调试 App 在 macOS Dock 中的大肥鱼娘图标，但反馈自行打包及开发启动显示铺满的方形、无圆角且偏大，要求统一并本地 commit。

## 目标
开发启动与 macOS 打包启动显示同一角色、圆角和留白比例。

## 非目标
不重新设计角色、不改页面头像和 UI、不清理系统图标缓存、不改 Runtime 或用户数据，不扩展 Windows/Linux 实机测试。

## 当前行为
`desktop:dev` 运行 Tauri dev；当前没有根 `dev` 命令。已核实锁定的 Tauri macOS 开发模式读取 ICNS 并直接设置 Dock 图标；源 ICNS、debug/release bundle 图标一致，原图均铺满方形。系统为 bundle 图标提供的圆角效果未包含在原 ICNS 中。

## 目标行为
macOS 开发可执行文件与 App bundle 使用用户认可的现有圆角图标，含相同透明边距。保留原有开发与打包流程。

## 功能需求
- 找出两条启动路径的实际图标来源，修复来源不一致的根因。
- 直接复用 NSWorkspace 从现有正确 App 导出的系统圆角图标，不生成另一版角色；检查打包后不重复叠加圆角或内缩。
- 保持现有其他平台资产与页面素材的适用语义；如需要转换，保留可重复的转换来源与命令。

## 边界条件
已有安装包不会由源码变更自动更新；不得将未重打的旧包声称为已修正。避免退出桌面时连带停止用户原有 Runtime。

## 技术约束
沿用 Tauri 2、单根 npm 工程；不新增无关依赖或包。由一个实施 Agent 修改、新独立 Agent 验收。变更范围仅限图标资源/对应原生配置与必要文档。

## 兼容性要求
角色、产品标识、窗口与后台生命周期不变。现有 `desktop:dev` 与 `desktop:build` 命令继续有效。

## 验收标准
- [x] 开发和 macOS bundle 的资源来源明确，圆角及可见边界比例一致。
- [x] 开发启动正常并嵌入符合参考的圆角资源；bundle 经系统读取后保持相同边界，无二次缩小。实际 Dock 截图如无法获取，应明确验证边界。
- [x] 未改变头像、用户配置、Runtime 或无关构建流程。
- [x] diff 与风险相称的检查通过，新独立验收 PASS。

## 待确认问题
无；用户已明确视觉目标和本地提交授权。
