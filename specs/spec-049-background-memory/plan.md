# 实施与验证

变更涉及 SQLite schema、回合完成状态和跨渠道隐私，按 S3 验证。队列负责完成状态、重试和关闭时的中断恢复。分析器从持久化来源读取发言人和有限前文，提取原句，按权限召回旧记录，并向写入层提交有证据的决定。写入层核对来源、归属和目标，再与任务完成状态一起落库。

验证使用临时 SQLite、模拟 OneBot 和受控的聊天模型。分别覆盖队列恢复、分析与写入边界，再通过正常聊天入口确认一条被暂停的整理任务不会阻塞后续回复。最后独立核对权限、幂等和迁移范围。

## 实施结果

每个来源消息最多一项任务。正常路径把消息或投递的完成状态与入队一起提交，只记录来源 ID；若队列表本身写入失败，保留已完成的回复并写审计。后台每次处理一项，分析失败最多尝试三次，运行中断留下的待办在原实例下次启动时继续。用户手动操作有优先权。模型输出只能指向本人原话，改期所指不清时保留原记录。

隔离联测暂停了后台模型，连续两次前台回复均先于记忆写入完成；恢复分析后，新聊天成功召回原话。用真实 DSH 连接回环 HTTP 夹具验证了后台请求，另以模拟 OneBot 和已下载的 BGE small INT8 核对了人物范围、投递和召回。数据库升级、幂等、重试上限、备份恢复及用户编辑保护有单独覆盖。未使用云端模型或真实账号。全项目 TypeScript 检查仍报告既有测试文件的类型错误，其中没有本次新增的队列、分析器或联测文件。

独立验收找到了两处更正问题。返工后，主人在私聊里更改群里已确定的安排，只有主人私聊视图显示私下更正；同一消息写了两次称呼，最终称呼与来源原句对应，仍可继续纠正。返工相关 21 项定向检查通过，生产 Node 构建通过。[独立复验](acceptance-r1.md)
