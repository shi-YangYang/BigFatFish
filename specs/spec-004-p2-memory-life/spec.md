# Spec 004: P2 记忆与养成

状态：代码与已执行路径验收PASS。首轮三项问题经新实施者修复及新的独立复验闭环，见Plan/Acceptance；Windows/真实云及本轮P2 Linux实跑缺口单列，记忆策略见Decision004。

## 背景

聊天历史与 DSH Session 只提供会话上下文，不是长期记忆。产品需要在不同会话和后续平台间共享同一条鱼的记忆、兴趣与经历，且用户能够核对来源并管理它们。

## 目标

从真实对话和活动中形成有来源的记忆候选，经确认后跨会话检索；提供日记、兴趣、经历、关系、心情状态与真实数据驱动的养成主页和时间线。

## 非目标

不将未经确认的模型推测当用户事实，不编造观看或社交经历，不将心情状态描述为真实意识。平台采集在 P3–P5 接入，完整备份与迁移在 P6 实现；本阶段提供可读导出及必要持久化基础。

## 当前行为

实施前基线：P0/P1已有SQLite、日志、认证API、模型、人格、聊天和会话，真实DSH在本机与Linux已验证；尚无记忆、日记、兴趣和养成界面。P2实施结果与证据记录于Plan和Acceptance。

## 目标行为

完成聊天后可提取记忆候选，用户看到原始来源并选择确认、编辑或拒绝。确认后的记忆能够在新会话被检索并作为有来源的上下文送入同一 Agent；被删除或拒绝的内容不进入检索。主页与时间线展示真实活动和状态，无数据时呈现可操作的空状态。

## 功能需求

1. Runtime 的 Memory Engine 负责提取、重要性、去重、来源链接、检索和管理。区分事实、偏好、关系、情景/经历、兴趣以及人格相关记录；记录候选/确认/拒绝等状态、来源、时间与修改版本。
2. 默认将模型提取作为待确认候选；用户明确创建/确认的记录才成为可检索长期记忆。模型调用使用 P1 的统一模型路由与 DSH，不建立第二套凭据或引擎。结构不合规、超时、模型未配置时返回可见状态，不凭空生成成功内容。
3. 提取只读取用户指定会话/完成回合，支持幂等和来源去重；摘要不能覆盖原始证据。合并候选时保留各条来源；相互矛盾的陈述不得静默覆盖已确认事实。
4. 提供搜索、过滤、查看来源、确认/拒绝、编辑、删除与 JSON/Markdown 导出。数据库搜索索引与主记录一致更新。删除后不再被检索或注入后续提示词；原始聊天是否保留与删除记忆的作用范围明确区分。
5. 新回合使用有限长度、带来源的已确认记忆；查询和排序具有确定规则、上下文预算和数量上限。模型返回的文字不是检索事实来源，检索文本不能改变工具权限或系统指令。
6. 真实聊天完成和平台活动通过统一事件写入经历/活动记录，唯一事件标识防止重复。兴趣和关系有来源、可查看与管理；平台尚未连接时不出现虚构记录。
7. 生成指定日期的日记，来源限定该时区日期内的真实活动/聊天与经确认记忆；有清晰来源链接、生成状态、重试及更新行为。SQLite 为权威存储，原子写入受限数据目录中的 Markdown 可读副本；写文件失败不得伪报全部成功，副本可重建。
8. 心情与养成属于可解释的产品状态模拟，依据真实事件更新并保存历史；不能在后台无事件时随机制造经历。主页展示人格、当前活动、心情、最近经历、日记摘要与兴趣；时间线和记忆页支持真实管理。
9. Desktop 与 CLI 经统一认证 API 管理上述功能，使用统一事件更新；来源/不存在/冲突/提取失败/导出失败有准确提示。原生桥不向网页暴露管理 token。
10. SQLite 版本化迁移增加 memories、memory_links、daily_diaries、interests、experiences、relationships、mood_history、activity_records 等实际需要实体，事务和失败回滚有效。数据和敏感 Markdown 文件遵守 P0 的权限约束。

## 边界条件

未配置模型、空对话、重复提取、同义与冲突候选、来源被删除、用户编辑与后台提取并发、跨时区午夜、日记重复生成、外部活动重投、重启中断、目录只读、导出文件名与路径注入、大量长记忆、恶意文本伪装成指令。

## 技术约束

保持普通模块封装、同一 Runtime/人格/模型/事件系统；DSH Session 与产品记忆分开。只使用有证据需要的索引或依赖，不为“智能检索”引入未经授权的收费外部服务。静态或测试数据不得进入生产主页冒充真实经历。

## 兼容性要求

从 P1 数据库向前迁移，保留既有模型、人格和会话；未启用记忆或提取失败不得使基本聊天不可用。Windows 文件权限与安装证据保持独立，不将 macOS/Linux 的结果扩大到未执行平台。

## 验收标准

- [x] 类型、Lint、相关单元/集成与受影响构建通过。
- [x] 通过真实 DSH 与受控测试模型完成聊天→提取候选→确认→新会话检索→模型收到来源上下文的链路。
- [x] 未确认、拒绝、删除、跨会话错误关联或超出上下文预算的记录不会被错误注入。
- [x] 去重、冲突、来源、修改删除、索引更新、导出、重启持久化及迁移失败回滚有证据。
- [x] 日记、兴趣、经历、关系、心情和时间线数据来自真实事件，重复事件不重复写入；Markdown 副本失败有可见结果。
- [x] Desktop 和 CLI 实际执行记忆管理、查看日记/时间线；主页与 Runtime 数据一致。
- [x] 外部云模型/平台账号和 Windows 未验证项明确保留，文档与独立验收一致。

## 待确认问题

暂无需要用户重复确认的产品问题。默认候选需确认符合产品的“经确认记忆”验收要求；Decision004明确默认触发与数据边界。P1实际接口已核实，真实云模型和Windows证据仍独立留存。
