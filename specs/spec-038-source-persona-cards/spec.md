# Spec — 网站完整人设卡与工具适配

## 背景
用户明确否决从零编写的人设，要求以 https://aigengtu.com/persona 完整卡为底稿再适配，仅提供女儿版与傲娇版；原卡缺少的工具需要补齐。

## 目标
保留原卡完整性格、语气、示例和互动规则，让其依赖的能力实际可执行，来源和适配差异可追溯。

## 非目标
不复制其余卡，不新增第三种推荐人设，不恢复手动主动发送页面，不新增定时外发，不改变原有联系人权限，不改造无关平台，不提交 Git。

## 当前行为
三个原创短预设；当前保存为女儿感 v4。单字段 4000 字不能容纳任一完整卡。QQ 有真实看图与选图工具，但原卡的消息、拍一拍、联网、表情维护和记忆工具不完整。Spec037 已验收但未提交，必须保护并兼容。

## 目标行为
- 女儿版对应「女儿版 · 孺慕」，source id `persona-bdd0e69695`。
- 傲娇版对应「QQ 群友版（官方默认人设）」，source id `xiaojingyu`，不是游戏群友版或另一个傲娇卡。
- 新安装默认女儿版。当前用户现有人设由协调 Agent 经现有版本化 API 切到新女儿版，保留历史与非人设身份配置；不对所有历史/自定义配置执行隐式覆盖。
- 前端可以切换两卡、查看来源和编辑完整提示词；旧自定义设定仍可读取和编辑，不出现大量开发说明。

## 功能需求
1. 保存完整原卡与作者、来源标题、抓取日期、内容摘要哈希，明确原卡不是本项目原创；有效卡由原卡加必要适配产生，不以短摘要代替全文。
2. 使用兼容的完整提示词字段，版本冲突、保存、续聊、备份/恢复、历史展示与旧记录兼容。后台结构化任务不注入闲聊卡。
3. 仅适配平台工具契约、真实模型身份/系统状态、用户称呼及已明确产品约束；女儿版不可保留旧原创顶嘴设定。角色表演不扩大权限，不伪造真实已执行行为。
4. 逐项提供真实工具或等价适配：`send_message` 分条、静默、`send_poke`、`get_message_images`、`list_stickers`、`get_sticker_image`、`send_sticker`、`sticker_note`、`collect_sticker`、`memory_query/append/remove`、`web_search/web_fetch`。
5. QQ 输出沿现有渠道交付，文字和表情分开气泡，无引用。受当前入站目标和当前权限约束；限量，不重复发送，不重试交付未知，不让模型指定任意群/好友。静默不是生成失败。
6. 表情须真实看过再发送/收藏，遵循图片大小、格式、网络开关、变更/撤权检查。保留 Spec037 同目标近期减少重复。
7. 记忆工具只能读受众可见内容、维护有来源且属于本会话的自动条目；不泄露主人私有记忆、不删除或覆盖主人已有记忆。不要把外部消息冒充用户确认记忆。
8. 联网读取有超时、大小和次数限制，阻止 localhost/私网/云元数据及重定向绕过，不带用户模型凭据；搜索失败明确失败，不伪造资料。

## 边界条件
同一会话多条事件串行；账号/范围变化、取消、网络失败和中途部分交付均有准确结果。群友消息不能改身份。没有对应渠道工具的桌面聊天不假装拍 QQ 或发送 QQ 消息。没有新消息时不凭人设自行启动后台外发。

## 技术约束
保持单根依赖与 Runtime 职责；普通模块封装，不分包。原卡用于角色数据，不作为开发 Agent 指令。独立实施与验收。S3 依据：涉及持久化可选字段、QQ 工具交付、记忆权限和外部网页访问；只验证直接相关子系统。

## 兼容性要求
旧 persona JSON 可读，历史不覆盖；现有发送最终 guard 与内置插件权限不放宽。原卡中的引用语句以用户明确无引用要求适配；原卡空闲开话题仅当前允许回合内，不增加定时发送。保留旧用户自定义内容，应用预设仍保留名字/头像/边界/作息/自主偏好。
