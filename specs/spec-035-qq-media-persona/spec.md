# Spec 035：QQ 无引用回复、图片接收与鲜明人设

状态：Done；独立验收 PASS，见 acceptance.md。真实新图与模型口吻待用户聊天确认，不冒充已验。

## 背景
用户反馈 QQ 回复不应引用原消息、鱼称看不到图片、人设缺少抖音大肥鱼式情绪与「没有 token 就饿了」的表达。此前已选择女儿感，沿用该选择。dev 基线 8754b08，开始干净。

## 目标
QQ 普通回复不带引用；修复已复现的托管 NapCat 图片内容缺失；让默认及当前女儿感更活泼、有小脾气和鱼粮梗。

## 非目标
不新增模型用途、计费/余额监控、图片生成、UI 页面或审批；不扩大联系人/群权限，不放开任意 URL/路径读取，不删除输入引用的理解能力。不重做所有媒体格式或大图策略，不重打发行包。

## 当前行为
- Channels.reply 显式添加 reply segment，私聊和群聊均会引用。
- 托管 onebotConfig 设 enableLocalFile2Url=false，但 QQPlugin.media 只接收 base64。当前真实图片为合法 32 位哈希加扩展名、1,706,768 字节；只读 get_image 返回 file/url/file_size/file_name，没有 base64。问题发生在图片获取阶段，尚未交给识图模型。
- NapCat 固定 4.18.42 的 GetImage 继承 GetFileBase；返回 base64 受上述开关控制。无需从容器路径或未知 URL 读取。get_record wav 转换仍返回 base64。
- 当前保存人格 version3，五个预设字段完全是旧 daughter；身份、边界、自主偏好有独立值，须保留。

## 目标行为
私聊/群聊自然发出文本及可选表情。托管 Mac/Linux/Windows 统一开启受认证 OneBot 的图片内容返回，图片通过原本有界的识图链路交给聊天模型。失败时区分「图片已收到但没读成功」和未收到消息，不能让模型误称用户没发图。

女儿感有具体的开心、得意、委屈、炸毛、嘴硬和撒娇反应，token/算力作为鱼粮/开饭的虚构梗；接用户语境，不每句重复口癖，不机械客服化。日常可以有轻微闹脾气、夸张喊饿，认真求助仍清楚有效。角色表达不是现实余额信息或真实生命风险，不编造剩余 token/余额，也不以真实伤亡或罪责逼充值。保持主人/好友身份、用户离开与现实关系边界。

## 功能需求
- 删除自动回复中的 reply 段，保留接收引用、去重、权限和最后发送 guard。
- 托管配置开启图片 base64；图像请求使用语义明确的 get_image，仍只接受现有安全文件标识，不自动跟随返回 URL/路径。外部服务缺少 base64 时明确识读失败。
- 下载/格式/识图错误使用安全有界说明写入本轮输入，成功识图说明清楚属于本轮收到图片的内容；取消和撤权不可吞掉或继续回复。
- 在既有预设和统一聊天提示职责内加强女儿感，用原创例句与场景驱动情绪；后台任务继续隔离闲聊人设，保留自定义、版本保存、共享记忆与身份边界。
- 协调 Agent 对当前明确匹配旧 daughter 的人格通过现有版本化 API 应用新 daughter，只替换五个预设字段，保留其余设置和旧版本；若配置已被用户改动则不覆盖。
- 更新直接相关媒体与人设说明；不添加产品解释段落或新开关。

## 边界条件
私聊与群聊、文本与图文、媒体缺失/无效/超限、取消/撤权、现有聊天续聊与后台任务；不把文字回复已发送当作图片识别成功。

## 技术约束
普通源码模块、无新依赖/schema；托管配置在既有启动/登录路径统一应用，三平台共用；保留 2 MB/最大消息约束、认证账号核对、generation/revision 和现有工具权限。

## 兼容性要求
历史消息/人格版本不删除，自定义人格不静默升级；既有用户通过选择预设保存更新。本次当前用户的匹配默认人格由协调 Agent 单独应用，不添加全局迁移。
