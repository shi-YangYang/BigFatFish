# Spec 032：长内容卡片内部滚动

状态：Done；R1返工独立验收PASS，见acceptance-r1.md。

## 背景
用户认可QQ记录卡片内部滚动，要求类似卡片同步。dev基线d94065d、工作区干净。当前QQ记录有高度限制，但其他动态列表、记录及长正文会撑开卡片和页面。

## 目标
让同类长内容区域共享高度限制和内部滚动，边缘滚动不传给外层页面；保持主要标题和表单操作易于访问。

## 非目标
不改变业务、加载数量、排序、权限、折叠交互或页面导航；不全局限制所有Card，不锁定外层页面，不引入依赖或自制滚动条。

## 当前行为
QQ记录已使用max-height:min(360px,50vh)、overflow-y:auto和overscroll-behavior-y:contain。B站搜索/观看记录、抖音任务结果、生活摘要/日记/经历、人设版本、运行日志及表情库等缺少一致的内容边界；QQ好友/群列表已有240px限制但仍可链式滚动。

## 目标行为
在明确的列表或长正文容器使用同一滚动规则。少量内容自然收缩，长内容可完整滚动阅读；滚到上下边缘不会带动页面。标题、筛选、创建/保存/刷新等主要表单操作位于内容滚动区外；记录自身按钮可随记录滚动。一个连续内容块只保留一个有效受限滚动层。

## 功能需求
- 明确接入B站搜索结果/观看记录、抖音最近任务及共用任务记录、生活概览的动态内容/最近日记、日记与经历/记忆记录、人设版本记录、运行日志、QQ表情库；相关来源原文在独立展示时也避免无界增长。
- QQ原有记录复用统一规则，好友/群列表保留较紧凑高度并补边缘滚动约束。
- 可使用Surfaces中的薄内容容器与共享CSS，或者显式class，业务卡片默认行为不变。仅对上述长内容接入，不用泛化后代选择器猜测哪些Card应滚动。
- 保留文本换行、全部数据、空态和所有按钮；考虑键盘访问与窄屏，控件焦点不能被滚动区域裁切。

## 边界条件
空列表、少量记录、长中文/URL/日志、低高度窗口、窄屏、列表内展开来源/版本、轮询更新；不添加固定最小高度或重复内外滚动。

## 技术约束
Desktop/Web现有React与beUI共用展示层。只改展示结构/CSS；不修改Runtime、API、依赖和数据。维持现有源码模块布局。

## 兼容性要求
QQ已确认滚动体验保持；其他页面正常纵向导航和表单提交行为保持，无数据迁移。

## 验收标准
- [x] 上述同类内容区域使用一致的内部滚动上限，长内容不再无界撑高页面。
- [x] 边缘滚动被限制在内容区，少内容自然收缩，全部内容和操作可达。
- [x] 标题/主要表单操作在列表外，避免同一长内容重复受限滚动。
- [x] 未改变数据和业务流程，必要局部检查与独立差异验收通过。

## 待确认问题
无。用户明确要求将既定体验同步到同类卡片，具体接入为展示层工程判断。
