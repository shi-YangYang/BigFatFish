# Spec 029：简化 QQ 连接与折叠交互

状态：Done；独立验收 PASS。

## 背景
用户要求本地 commit 后修复折叠框悬浮、点击观感，以及 QQ 快速连接后仍需再次启动的重复流程。开始时 dev 干净，上一阶段已提交为 191ab88；持续每阶段本地 commit 授权有效。

## 目标
一次连接操作完成准备与启动，已配置同一账号登录后自动连接；QQ 常用内容无需逐层展开，剩余折叠项交互平稳。

## 非目标
不新增平台、改回复权限、默认选主人/好友/群、不修改 NapCat 源码、不操作真实 QQ 发消息、不重新打包或推送。

## 当前行为
“快速连接”只是模式按钮；组件安装、启动、保存启用分离。QQ 好友、群、表情、记录多层折叠。共用 Disclosure 使用整行按钮 pressScale 及多层 layout 投影，展开时可能产生变形。

## 目标行为
- QQ 默认展示扫码连接，主操作“连接 QQ”；自动安装缺失组件并启动，显示必要下载/扫码/失败状态，可取消。
- 已保存相同托管账号时，显式连接后登录即恢复已保存设置，无第二个启用步骤。首次/换账号只保留必要的主人与范围配置，按钮“保存并连接”。之后“保存设置”。
- 保留已有服务入口，作为次级连接方式；保存即连接，取消重复启用勾选。保留明确断开/重新连接与失败重试。
- QQ 登录/状态卡片之后使用“回复设置 / 表情 / 消息”少量页签。好友、群为清楚的直接分组或同级选择，不能继续层层折叠；表情直接展示；消息中的发送、最近消息及操作记录同级组织，无嵌套折叠。
- 所有共用 Disclosure 保留 beUI、键盘/焦点/aria/inert，整行不按压缩放、不波纹、不扭曲内容；浅海蓝轻悬浮、统一内边距与箭头。

## 功能需求
连接编排归属 ManagedQQ，页面卸载后后台操作仍可完成，不能靠前端定时拼接安装/启动。现有明确暂停、取消、账号变化、配置版本冲突必须阻止迟到恢复。失败可重试但不能伪造成功。运行态与表单草稿分开，轮询不覆盖正在编辑的内容，页签切换不丢未保存的回复设置。

## 边界条件
首次安装/已安装/已登录但暂停/同账号重连/扫码换账号；重复点击；安装中取消与 Runtime 关闭；外部已连接时不接管；保存期间错误与版本冲突；380px 窄屏与长昵称。

## 技术约束
沿用 React/beUI、现有 token、40px 操作高度与普通源码模块。没有新依赖、schema 或目录迁移。仅修改共用折叠职责层及 QQ 直接受影响路径。

## 兼容性要求
现有组件 install/start、CLI 与配置字段保留；可新增受现有认证保护的 connect 编排入口。仍由真实 OneBot 健康确认已连接，未配置时不自动授权任何联系人。

## 验收标准
- [x] 单次连接可以跨安装和启动到扫码；同一已配置账号不需二次启动。
- [x] 首次及账号变化不自动猜主人或扩大授权；保存即连接。
- [x] 取消/暂停/配置变化/重复请求不导致迟到启用或资源泄漏。
- [x] QQ 常用设置、表情和消息由明确页签组织，无多层折叠；已有服务入口可用。
- [x] 折叠悬浮/点击/展开无缩放扭曲，键盘及隐藏状态可达性保持。
- [x] 隔离桌面与窄屏 UI 检查、相关生命周期测试通过；不声称真实 QQ 验证。

## 待确认问题
无。必要主人选择和权限边界沿用用户已经确认的业务规则。

## 扫码后等待消息服务
扫码确认与 OneBot 可用之间允许存在启动窗口。等待期间不重复写入同一账号的配置、不提示重启或再次扫码；只有核实消息接口账号后才恢复原授权。等待必须有界，持续不可达、账号不符或凭据错误应能区分，并允许重试或断开。停止、取消或换账号后不得复用上次的连接结果。不改变原版 NapCat 与本机 QQ 的隔离方式。
